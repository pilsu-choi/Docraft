## 한 줄 요약

**OCR이 1차로 읽은 결과를 받아서 여러 방법으로 맞는지 따져 보고, 칸마다 "믿어도 되는 정도"를 표시해 돌려주는 검수 단계**다.

> 비유: OCR이 **답안을 쓴 학생**이라면 하네스는 **채점 선생님**, Docraft는 헷갈릴 때 **다시 읽어 달라고 맡기는 돋보기 담당**이다.
> 선생님은 답을 새로 쓰지 않는다. 채점하고, 근거가 확실한 것만 고친다.

```
청구서 이미지 → [Agentic OCR: 1차 판독] → [하네스: 검수] → 고객사 DB 적재
                                           ↕ (필요할 때만)
                                        [Docraft: 다시 읽기]
```

## 처리 흐름 (6단계)

| 단계 | 쉬운 말 | 하는 일 |
|---|---|---|
| ① 접수 | 서류 받기 | OCR 결과(JSON)와 원본 이미지가 짝이 맞는지 확인하고 접수번호를 붙인다 |
| ①' 서류 종류 재확인 | "영수증이 맞나?" | 이미지 제목 줄을 다시 읽는다. OCR이 판단한 서류 종류가 틀렸으면 Docraft에 맞는 양식으로 전체를 다시 읽힌다 |
| ② 정리 | 답안 정돈 | 칸 이름을 통일하고, 명백한 표기 오류(항목명을 잘못 읽은 것, 열이 뒤바뀐 것 등)를 바로잡는다 |
| ③ 검사 (3가지를 동시에) | 채점 | 규칙 검사(34개), 기준표 대조(질병코드 KCD·수가코드 EDI), 다시 읽기 대조(기본 꺼짐) |
| ④ 판정 | 점수 매기기 | 검사 결과를 모아 칸마다 7가지 등급 중 하나를 붙인다. 판단은 이 한 곳에서만 한다 |
| ④' 애매한 서류 재확인 | 한 번 더 보기 | 등급이 "애매"나 "해결 못 함"인 서류는 문제가 된 항목만 Docraft에 다시 읽혀 재판정한다 |
| ⑤ 결과 내보내기 | 답안 돌려주기 | 원래 구조는 그대로 두고 등급과 근거를 덧붙인다. 확실히 고친 값은 반영하고, 원래 값도 함께 남긴다 |
| ⑥ 기록 | 보관 | DB와 로그에 이력을 남긴다 |

## 7가지 등급

| 등급 | 쉬운 뜻 |
|---|---|
| `pass` 통과 | 모든 검사를 통과했다. 그대로 믿어도 된다 |
| `repaired` 고침 | 원래 값이 규칙상 불가능해서 확실한 근거로 고쳤다 (원래 값은 보관) |
| `inferred` 채움 | 비어 있던 값을 기준 DB에서 찾아 채웠다 |
| `swap` 자리 바꿈 | 질병코드와 병명의 짝이 엇갈려 있어서 맞춰 놓았다 |
| `ambiguous` 애매 | 가능한 답이 여러 개다. 자동으로 고르지 않고 후보만 적어 둔다 |
| `unresolved` 해결 못 함 | 틀린 것 같지만 고칠 근거가 없어서 원래 값을 유지한다 |
| `out_of_scope` 대상 아님 | 기준 DB 범위 밖이라 검사하지 않았다 |

중간에 사람이 검토하는 단계가 없다. 그래서 모든 서류를 적재하고, 등급이 **신뢰도 표시** 역할을 한다.
하네스는 확인이 필요한 칸 목록(`review_paths`)을 넘기는 데까지 책임진다.

## 34개 규칙

서류 종류별 세 묶음이다(영수증 11 + 세부내역서 10 + 진단서류 13).
요약하면 **"금액 계산이 맞나, 코드가 실제로 있나, 형식과 앞뒤가 맞나"**를 본다.
규칙에 걸려도 곧바로 틀렸다고 판정하지 않는다. 규칙 결과는 판정 근거 중 하나로만 쓴다.

### 진료비영수증 (11개)

| 무엇을 보나 | 규칙 |
|---|---|
| 금액 계산 (7) | 총액 = 급여 + 비급여 / 환자부담 = 본인부담 + 전액본인 + 비급여 / 급여 = 본인 + 공단 + 전액본인 / 비급여 = 선택진료 + 선택진료외 / 총액 = 환자부담 + 공단부담 + 상한초과 / 납부할 금액 = 환자부담 − 이미 낸 돈 − 각종 감액 / 낸 돈 합계 = 카드 + 현금영수증 + 현금 |
| 위아래 대조 (2) | 오른쪽 요약 칸의 총액이 아래 표 합계와 같은가 / 합계 행이 각 열을 더한 값과 같은가 |
| 표 모양 (1) | 표의 행과 열이 밀리거나 빠지지 않았는가 |
| 형식 (1) | 질병군(DRG) 번호가 "영문 1자 + 숫자 4~5자리"인가 (OCR이 사업자번호나 병실번호를 넣은 사례가 있었다) |

### 진료비 세부내역서 (10개)

| 무엇을 보나 | 규칙 |
|---|---|
| 행 계산 (2) | 한 줄 금액 = 단가 × 횟수 × 일수 / 한 줄 총액 = 부담금 합 × 일수 |
| 열 합계 (3) | 각 열을 모두 더한 값 = 맨 아래 총액 / 급여총액 = 본인 + 공단 + 전액본인 / 비급여총액 = 선택진료 + 선택진료외 |
| 기준표 대조 (4) | 수가코드(EDI)가 실제로 있는 코드인가 / 코드와 항목명이 서로 맞는가 (안 맞으면 코드를 잘못 읽었을 수 있다) / 코드가 비었으면 항목명으로 후보 찾기 / 단가가 기준 단가와 맞는가 |
| 표 모양 (1) | 행과 열이 맞는가 |

### 진단서·소견서·입퇴원확인서·수술확인서 (13개)

| 무엇을 보나 | 규칙 |
|---|---|
| 질병코드 형식 (2) | 코드 모양 정리(점 제거 등) / "영문 1자 + 숫자 3~6자리"인가 |
| 질병코드 기준표 (4) | 실제로 있는 코드인가 / 코드와 병명이 맞는가 / 코드만 있으면 병명 채우기 / 병명만 있으면 코드 찾기 |
| 코드 정리 (3) | 여러 코드가 중복됐는가 / 코드와 병명 짝이 엇갈렸으면 맞추기 / 좌우·부위를 나타내는 코드 자리와 병명("좌측" 등)이 맞는가 |
| 개인정보·날짜 (4) | 성별이 주민번호 뒷자리와 맞는가 / 생년월일이 주민번호 앞자리와 맞는가 / 사고일 = 진단일과 첫 검사일 중 빠른 날인가 / 최종진단·임상추정 값이 Y/N인가 |

## Docraft 다시 읽기: 문제 칸만 읽는 예시

**세부내역서 한 줄**

- OCR 결과: 단가 4,500 · 횟수 2 · 일수 (빈칸) · 금액 9,000
- "단가 × 횟수 × 일수 = 금액" 규칙에 걸려 해당 칸이 **해결 못 함** 등급이 된다
- Docraft에 **"항목내역" 표만** 다시 읽어 달라고 요청한다 → 결과: 횟수 1 · 일수 2
- 4,500 × 1 × 2 = 9,000이 되어 규칙을 통과한다 → 두 칸 모두 **고침** 등급이 되고 값이 반영된다

**영수증 병원명**

- 병원명이 비어 필수 칸 검사에 걸린다 → Docraft에 `keys: ["병원명"]`만 요청한다

**정확히 해 둘 점**

- 보내는 이미지는 **그 페이지 한 장 전체**다. 대신 읽을 항목 이름(`keys`)을 지정한다.
- 표 안의 칸은 칸 하나만 지정할 수 없어서 **표 하나를 통째로** 읽는다. 판정에는 문제된 줄과 관련된 칸만 반영한다.
- 이미 통과한 칸은 다시 묻지 않는다.

## 전체를 다시 읽는 경우

| 경우 | 다시 읽는 범위 | 설명 |
|---|---|---|
| 서류 종류가 틀렸을 때 (①') | **서류 전체** | 제목 줄 기준 서류 종류가 OCR 판단과 다르면 올바른 양식으로 처음부터 다시 읽는다. 이 서류는 이후 ④'를 하지 않는다 |
| 다시 읽기 대조를 "전체" 모드로 켰을 때 (③, `REREAD_MODE=full`) | 모든 칸 | 설정으로만 켤 수 있다. **기본은 꺼짐**이다. 서류마다 수십 초가 걸리기 때문이다 |
| 필수 행 누락 (룰 2: 진찰료·CT 행) | 표 전체 | 항목내역 표를 통째로 다시 읽고, 빠진 행을 찾으면 표 끝에 붙인다. 붙인 행의 금액은 계산 규칙이 맞을 때만 받아들인다 |
| 표 안의 칸이 문제일 때 | 표 전체 | 위 예시와 같다 |
| 애매·해결 못 함 칸 (④') | **해당 항목만** | 기본 동작이다 |

**다시 읽지 않는 경우**: 여러 페이지짜리 서류(Docraft는 한 장씩만 받는다), 대상 7종 밖의 서류, 이미지 없이 들어오는 동기 방식 요청.
이때는 하네스 판정으로 끝난다.

## 예상 질문과 답변

- **하네스가 직접 AI로 읽는가?** 읽지 않는다. 이미지를 다시 읽는 일은 Docraft(PaddleOCR + Qwen3-VL)가 맡고, 하네스는 비교와 판정만 한다. 판단 기준을 한 곳에 모으려고 9/27에 역할을 나눴다.
- **Docraft를 매번 부르는가?** 부르지 않는다. 서류 종류가 틀렸을 때와 애매·해결 못 함 칸이 있을 때만 부른다. 한 번 부를 때 수십 초가 걸려서 이렇게 제한했다.
- **확실하지 않은 값도 고치는가?** 고치지 않는다. 인쇄되지 않은 값을 추정해서 채우면 정답지 채점 결과가 오히려 나빠져서 그 기능은 뺐다. 후보가 여러 개면 적어 두기만 한다.
- **효과는?** 표본 7종 210장에서 OCR 단독 87.0%가 하네스 적용 후 93.0%로 올랐다. 개선분 대부분은 서류 종류 재확인에서 나왔다. **정답지를 사람이 검수하기 전 수치**라는 점을 함께 밝힌다.
- **한 줄 답변(재판독 범위)**: "서류 종류가 틀렸을 때만 전체를 다시 읽고, 나머지는 문제가 된 항목(표라면 그 표)만 다시 읽습니다. 매번 전체를 다시 읽는 모드도 있지만 시간이 많이 걸려서 꺼 두었습니다."

## 용어 설명

| 용어 | 뜻 |
|---|---|
| AO (Agentic OCR) | 상위 시스템의 1차 판독기. 하네스의 입력을 만든다 |
| Docraft | 이미지를 다시 읽어 주는 판독 서비스. 읽은 값만 돌려주고 판단은 하지 않는다 |
| KCD | 한국표준질병사인분류 코드 (질병코드) |
| EDI 수가코드 | 건강보험 진료행위·약·치료재료 코드 |
| DRG | 포괄수가 질병군 번호 |
| 동기/비동기 요청 | 동기는 결과를 바로 기다리는 방식으로 이미지가 없다. 비동기는 접수 후 나중에 결과를 받는 방식으로 이미지가 함께 온다 |
