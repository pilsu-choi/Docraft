## 문제와 현재 흐름

Parse는 PDF 텍스트 레이어 또는 원격 PaddleOCR layout 결과에서 블록·표·좌표를 만든다. 선택적으로 PP-OCRv5 줄 좌표와 괘선 표 격자를 보강한다. Extract는 페이지별 VLM 결과를 합치고 OCR 행·줄에 값을 다시 연결한다. 일반 문서 API의 기존 검사는 JSON Schema와 `confidence < 0.7`뿐이었다. 의료문서 `/api/verify`는 `rules.run` 반복 교정·Judge 판정·최종 룰 재검사를 수행하지만, OCR 근거와 최종 값의 관계를 필드별 상태로 내보내지 않았다.

## 변경한 계약

- 근거의 `source_text`는 추출값의 복사가 아니라 실제 OCR 줄·표 셀·블록 원문이다. 출처가 없으면 `null`이다. 블록·행·열, 매칭 종류, 원본 페이지 크기도 근거에 둔다.
- `engine.assess`는 필드별 `status`(`PASS`, `SUSPICIOUS`, `UNRESOLVED`, 교정 뒤 `CORRECTED`), `issue_codes`, `action`(`ACCEPT`, `RECHECK`, `REVIEW`), `stage`, `provenance`를 계산한다. `stage: undetermined`는 Parse와 Extract 중 원인을 증거만으로 구별할 수 없다는 뜻이다.
- `/api/read`는 기존 `fields`와 `groundings` 외에 `field_quality`를 반환한다. 경로는 스칼라 `병원명`, 표 셀 `병명내역/0/열` 형식이다. `/api/verify`는 `documents[i].verify.field_quality`를 반환하고 최종 룰 검사 뒤의 이상을 합친다. 사람이 고친 일반 문서 값은 `CORRECTED`로 기록한다.
- `no_source`, OCR 근사 일치, 중복 위치, 명시된 key의 누락, 먼 label, 구조가 불확실한 행 충돌은 `RECHECK` 신호다. 스키마 위반, 페이지 밖 좌표, 괘선 표에서 검증된 행 불일치는 `REVIEW`다. 소프트 신호는 결과를 임의 교정하지 않는다. 일반 문서 API는 두 신호 모두 `needs_review`에 남겨 완료 상태와 미확정을 혼동하지 않게 한다. 이 선택은 자동 처리율을 낮춘다.
- PaddleOCR가 요청 페이지 수와 다른 페이지 수를 반환하면 일부 성공으로 숨기지 않고 ParseError를 낸다.

## 검증과 측정

전체 테스트 `551 passed`. 새 변형 테스트는 한 글자 오인식, 출처 부재·중복, 빈 값과 명시 key, 먼 label, 잘못된 행·페이지 좌표, 누락 페이지 응답을 포함한다. 실제 바이트는 GIF인데 이름이 `.TIF`인 표본의 OCR 422 실패는 이미지 디코딩 후 PNG 전송으로 고쳤다.

기존 `accuracy-20260922`의 76건 Parse·raw Extract 캐시를 새 코드에서 다시 근거 연결해 평가했다. 이 캐시는 새 provenance를 기록한 결과가 아니므로 운영에서의 탐지율을 직접 증명하지 않는다. raw 단계의 동일한 라벨과 예측을 비교하면 스칼라 정답 798개 중 362개에 소프트 경고가 생겼고, 오답 72개 중 23개, 라벨이 빈데 값을 넣은 94개 중 55개에 경고가 생겼다. 스칼라 정답의 약 45%를 경고하는 현재 신호를 모두 자동 차단에 쓰면 처리율이 크게 떨어진다. 값이 OCR에 존재해도 다른 날짜·금액 역할을 고른 오류는 여전히 PASS일 수 있다. 전체 10,582 leaf 중 8,959 PASS, 나머지 1,623은 근거·관계·형식의 재확인 또는 검토 신호였다(괘선 근거가 없는 캐시의 행 충돌은 소프트 분류).

신규 독립 표본은 7종×5건, 총 35건을 기존 76건과 SHA-256으로 중복 제거해 선정했다. Sol·Terra·Luna가 원본 이미지를 직접 판독한 라벨은 `silver`, `unreviewed`, `agent-visual`로 보관하고 판독 불가 셀은 `provenance.unknown_fields`로 실제 빈칸과 구분한다. 35/35 원본 해시와 스키마 키 일치를 확인했지만 독립 검수한 gold로 자동 승격하지 않는다. 15건 선행 E2E의 raw→rules에서 알려진 값 정답 수는 170/199로 같고, 라벨 null에 예측값을 채운 건수는 59→72로 늘었다. 추가 13건의 발생 단계는 주민번호에서 성별·생년월일 파생 6, OCR 라벨 옆 차트번호·병원주소 보충 3, 문장 속 치료명 행 생성 4이다. 뒤 7건의 문자열은 OCR 원문에 존재하지만 해당 필드의 올바른 값인지는 맥락 검토가 필요하다. 앞 6건은 직접 인쇄값과 파생값의 채점 계약도 분리해야 한다. 이 수치만으로 규칙 오류나 정답을 단정하지 않는다.

35건 평가에서 병합된 영수증 표의 위쪽 제목 `전액 본인부담`을 아래쪽 실제 `공단부담금` 열보다 우선해 금액을 옮기는 규칙 오류를 발견했다. 실제 금액 열 머리글을 우선하도록 고친 뒤 같은 Parse·Extract 캐시로 재채점하니 영수증의 알려진 비어 있지 않은 값은 rules 단계 920→948/1026(+28), 전체 35건은 2035→2063/2217(+28)이었다. 기존 76건 캐시의 영수증 결과는 4263/4479, fp 12, strict 2929로 수정 전과 같았다. 회귀 포함 전체 테스트는 `551 passed`이다. 영수증 strict 점수가 여전히 낮은 이유 중 139셀은 그룹 제목 `급여` 57·`비급여` 82의 `0`(라벨·스키마 지시)과 `null`(기존 규칙)의 표현 차이다. 원본 그룹 제목 자체에 숫자 0이 인쇄된 것은 아니며, 이 null/0 계약을 통일하는 작업은 남겼다.

`PASS`는 OCR 텍스트와 현재 검사의 일치이지 이미지 픽셀의 참값 인증이 아니다. OCR 근거가 없으면 재확인 대상으로 남는다. 이 표는 당시 구현 상태다. 2026-09-27 [자동 재처리 루프](2026-09-27-auto-reprocess.md)가 추가되어 `/api/read`와 일반 추출에서 제한된 ROI crop·VLM 재호출이 실행된다. 판독 불명확한 후보는 계속 미확정으로 남긴다.

## 이미지 변형 실험 (Update)

gold 4건에 원본·회전·흐림·중앙 가림을 적용한 16건을 평가했다. 변형별 4문서·양성 라벨 505개 기준 rules 일치값은 원본 485, 회전 488, 흐림 488, 가림 485였다. 엄격 일치는 각각 410, 303, 311, 302다. 두 방식의 큰 차이를 숨기지 않는다.

캐시 Parse·Extract를 품질 검사한 재확인 필드는 원본 213/581, 회전 269/613, 흐림 237/581, 가림 219/581이다. 추출 배열 길이가 변해 분모도 달라진다. 회전·흐림 등에서 경고 수가 늘었다는 관측이며, 검출 정답 라벨이 없으므로 탐지 recall을 의미하지 않는다. 중앙 가림이 어느 정답 필드를 실제 가렸는지의 필드별 가시성 라벨은 없다. 실행 도중 파서 형식 수정이 반영돼 source fingerprint가 변경됐으므로 확정 버전의 통제 실험으로 간주하지 않는다. 상세 결과는 `/tmp/parse-extract-quality/perturbation/summary.json`이다.

## 남은 한계

OCR 근거 일치는 이미지 픽셀의 정답을 보장하지 않는다. `PASS`는 구현된 검사 통과일 뿐 최종 정확성 인증이 아니다. OCR가 누락했지만 VLM이 올바르게 읽은 값은 `RECHECK`로 남는다. 같은 값이 문서의 다른 역할에도 인쇄된 경우 일반 근거 검사만으로 역할을 확정할 수 없다. 마스터·산술 관계는 기존 의료문서 룰이 다루는 범위에 한정된다. 자동 선택적 이미지 재확인과 그 결과의 독립 재검증, 영역 재파싱, 페이지 경계·표 연속성 검증, 고객 문서의 대규모 gold 평가는 완료되지 않았다. 이번 변경으로 정확도 97%를 달성했다고 주장하지 않는다.

## 수정 전 조사

Docraft: Parse는 PDF 텍스트 또는 원격 Paddle layout을 사용하고 OCR line bbox 보강, 표 grid 복원, 셀 VLM refine 후 페이지 block을 저장한다. Extract는 페이지 chunk별 LLM·이미지 처리와 병합을 거쳐 block·행·OCR line 기반으로 출처를 연결한다. 일반 `engine.validate`는 JSON Schema와 confidence 임계값 중심이다. 의료문서별 검증·교정은 `backend/rules.py`, 평가 비교는 verify 경로에 있다. 출처의 `source_text`가 실제 OCR 원문 대신 추출값으로 채워지는 경로와 범용 교정 후 재검증·상태 전달이 조사 대상이다.

Harness: 입력 정규화 → 규칙·재판독·마스터 → 판정 → 결과 산출 순이다. `bench.py`는 라벨 필드가 추출 또는 판정에서 누락되면 unmatched로 제외할 수 있어 전체 필드 정확도의 분모로 부적절하다. 기존 recall·false positive·correction precision·auto confirm 지표를 확장하고 실패 원인 보고를 추가한다. 이미지 재판독 없이 Parse와 Extract 원인을 확정할 수 없는 경우에는 원인 미상으로 유지한다.
