## 이미 구현된 부분

### 추가 논문의 실제 참고 범위

하네스에는 근거·규칙·마스터·선택적 재처리가 이미 있으므로 새 오케스트레이터를 추가하기보다 빈틈을 평가한다. 값·페이지·근거 셀·라벨 관계·근거 없음 상태를 보존하고, 값 일치와 위치·역할 일치를 분리해 검사한다. 값이 같아도 다른 금액 열에서 가져온 사례, 행 전체 누락, 교정으로 정답을 망친 사례를 포함한다. 모델이 생성한 bbox와 confidence 자체는 독립적인 원문 검증으로 간주하지 않는다.

오류 유형별 도구 선택은 예산이 있는 고정 라우팅으로 실험한다. 근거 검증의 개선 폭과 추가 지연을 측정하고, 모든 field에 추가 VLM 검증을 호출하지 않는다. 자동 적재 비율과 그 집합의 오류율을 함께 보고하며, 99% 개선을 논문만으로 보장하지 않는다. 기존 분석의 누락 우선순위를 이 논문 목록만으로 뒤집지 않는다.

Docraft dev 코드에는 인쇄 열 순서에 따른 rowmajor 출력, 회전 정규화, 여러 쪽 묶음 처리, 분류·날짜 이어 채우기, 열 맞바꿈 근거 검사, 일부 ROI 재판독이 있다. harness에는 인쇄 열·필수 셀 누락 검사도 있다. 이를 신규 기능으로 제안하지 않고, 아래 실제 차이를 실험한다. 구현 존재와 실제 배포 활성 여부는 별개다.

- `backend/engine.py::_chunk_text`: 블록 text를 연결하고 긴 단일 블록은 길이 상한에서 잘라낸다. 명시적인 행·셀 좌표를 보존한 별도 입력 표현을 실험할 여지가 있다. 기존 블록 text에 HTML 등이 포함될 수 있으므로 모든 현행 입력이 구조 없는 평문이라고 단정하지 않는다.
- `backend/engine.py::_read_rows`: 열별 값 배열의 길이를 강제하지만 출력 계약에 원문 행 ID는 없다. 행 누락·중복의 독립 탐지가 필요하다.
- `backend/engine.py::_page_images`: 추출에 페이지 이미지를 첨부한다. 첫 추출의 표별 크롭 입력은 기존 재처리 ROI와 다른 실험이다.
- `normalizer/coverage.py::expected_cells`: 이미 존재하는 출력 행의 인쇄 필수 칸을 검사한다. 원문에 있는데 출력에서 행 자체가 빠지는 문제는 별도 대응이 필요하다.

## 1 원문 행과 출력 행의 대응 검사

OCR의 셀·줄 좌표와 명칭·코드·금액 근거로 잠정적인 원문 행 목록을 만든다. 각 행에는 페이지·표·원문 y범위와 행 ID를 붙이고 항목·소계·합계·분류 제목·반복 머리글을 구분한다. 줄바꿈된 명칭 두 줄을 별도 항목으로 세지 않도록 셀 병합 범위, 코드·금액 앵커, 세로 간격을 함께 사용한다.

추출 결과를 원문 행 목록과 페이지·순서·값·위치로 대응시킨다. 단순 개수 비교보다 단조 순서 동적계획법 또는 정렬된 일대일 매칭을 시작 후보로 두고, 생략·다대일 모호성을 표시한다. 같은 코드·금액이 반복되는 정상 항목은 별도 원문 위치를 가진 독립 행으로 유지한다.

행 ID를 입력·출력에 넣는 방식과 출력 후 오프라인 매칭 방식은 별도 비교한다. 원문 행 ID를 무조건 하나씩 채우게 강제하면 잘못 구성된 행 목록이 환각을 유발할 수 있으므로 unreadable·unmatched·extra를 허용한다. 원문 목록 자체의 오류도 사람 검수로 측정한다.

추출에서 빠진 행은 그 위치를 재판독하며 출력에만 있는 행은 근거 부족으로 표시한다. OCR 자체가 누락한 영역에는 독립적인 숫자 줄·구획선 등 원문 커버리지 신호가 필요하다. 기존 OCR과 같은 실수를 공유하는 행 목록만으로 완결성을 보장할 수 없다.

핵심 지표는 행 recall·precision, 누락 탐지 recall·오탐률, 반복 항목 보존, 문서 완전 정답률이다. 참고: [ExtractBench](https://arxiv.org/abs/2607.29677)의 record completeness 관점. 이 행 대응 알고리즘 자체가 논문에서 검증됐다는 뜻은 아니다.

## 2 좌표와 병합 관계를 보존한 간결한 입력

현행과 동일 OCR 결과를 다음 세 표현으로 직렬화해 비교한다: 현행 블록 text, 공백 정렬을 통한 열 위치 보존, 행·열 ID와 병합 관계를 명시한 간결한 셀 표현. 한글 문자열의 문자수만으로 공백 정렬하지 않고 원문 x좌표로 열을 결정한다.

머리글은 `급여/일부본인부담/본인부담금`처럼 상위·하위 관계를 보존한다. 물리적 빈칸, 인쇄되지 않은 열, 읽지 못한 값은 서로 다른 내부 상태로 유지한다. 모델에 같은 null을 주는 경우에도 후처리에 상태 근거를 보존한다. 병합 칸의 값을 여러 행에 복제할 때 원본 span을 남겨 실제 여러 번 인쇄된 값과 구분한다.

입력에는 필요한 행·열 관계만 담고 모든 문자 좌표를 장황한 JSON으로 늘리지 않는다. rowmajor 출력은 유지하고 진단용 짧은 행 ID 외의 이유 설명을 출력에서 요구하지 않는다. 입력 형식에 따라 토큰 수가 늘 수 있으므로 정확도와 실제 전체 지연을 함께 비교한다.

참고: [VAREX](https://arxiv.org/abs/2603.15118)는 입력 모달리티와 레이아웃 보존 텍스트의 영향을 비교한다. 합성 정부 양식이므로 보고된 개선 폭은 한국 의료비 문서로 전이할 수 없다. [Table Meets LLM](https://arxiv.org/abs/2305.13062)은 형식·순서·구분 표시의 영향을 다루며 특정 형식의 보편적 우월성을 보장하지 않는다.

## 3 전체 페이지 대신 표와 문맥을 함께 입력

첫 추출의 이미지 입력을 비교한다: 전체 페이지, 표 크롭과 머리글·분류 영역, 저해상도 전체 페이지와 원본 해상도 표 크롭. 표 밑의 합계·주석 또는 옆의 열 라벨이 의미 결정에 필요하면 크롭에 포함한다. 원본 숫자가 작은 표를 모델 입력 직전에 전체 페이지로 축소하는 문제를 줄이는 가설이다.

크롭의 폭·높이·전송 해상도·시각 토큰을 기록한다. 이미지 수를 늘리는 것이 지연을 줄인다고 전제하지 않는다. 한 칸씩 수십 번 호출하지 않고 의심 행들을 한 표 영역으로 묶는다. 좌표 변환을 보존해 모델 근거를 원본 페이지로 복원한다. 머리글·합계가 잘린 사례, 크롭 경계에 걸린 문자, 좌표가 부정확한 파서 결과도 검증한다.

참고: [MinerU2.5](https://arxiv.org/abs/2509.22186)의 전체 레이아웃과 고해상도 국소 인식 분리 원리. 모델 교체나 학습 기법을 채택하는 제안이 아니다.

## 4 행 경계를 지키는 분할과 원문 위치에 근거한 병합

이미 있는 페이지 묶음 처리를 넘어, 단일 페이지의 긴 표는 완전한 행 묶음으로 나누는 실험을 한다. 현재 [쪽 묶음 기록](2026-10-03-pagewise-table.md)은 조밀한 70~100행 쪽에서 출력 상한이 아닌 `finish_reason=stop` 상태의 JSON 실패가 남는다고 적었다. 따라서 출력 토큰 상한만 늘리기보다 단일 페이지 내부 행 분할을 우선 비교한다. 각 묶음에는 머리글·현재 분류와 필요할 때 경계 문맥을 포함한다. 문자 길이에서 잘리는 방식과 비교하고 실제 행수·열수 기반 출력 길이 추정을 측정한다.

묶음의 겹친 부분은 페이지·행 ID·원문 영역으로 중복 제거한다. 내용이 같은 행이라는 이유만으로 삭제하지 않는다. 같은 처치가 여러 번 기재된 정상 행과 겹친 영역에서 다시 출력한 동일 원문 행을 구분한다. 페이지 연결에는 열 배치·이어지는 표 근거·분류 범위를 사용하고 확실하지 않은 쪽 경계는 알린다.

현재 문서 전체의 다수결 열 배치는 중간에 서식이 바뀌면 부적합할 수 있다. 머리글·열 x위치가 명확히 바뀐 곳에서는 별도 표 구간으로 분리하고 머리글이 없는 이어진 쪽에서만 호환되는 앞쪽 배치를 상속하는 실험을 한다. 페이지 경계에서 잘린 한 항목의 연결은 항목명 줄바꿈·코드/금액·열 배정 근거가 있을 때만 허용한다. 이 두 사례는 현재 평가 자료에서 충분히 검증되지 않아 새 홀드아웃을 먼저 확보해야 한다.

비교 지표는 경계 행 누락·중복·분류 손실, 출력 잘림, 재호출, p95 지연이다. 관련 평가 자료: [PubTables-v2](https://arxiv.org/abs/2512.10888).

## 5 후처리는 값을 만들어 채우기보다 원문 후보를 검증한다

숫자·날짜·코드 정규화는 raw 값과 함께 보존한다. 소수점·음수·괄호·빈칸·미인쇄를 구분하고, 숫자 비교에는 Decimal과 문서에 맞는 단위·반올림 정책을 사용한다. `O→0` 같은 치환은 문자의 위치·역할과 원문 후보가 확인될 때만 한다.

열 배정은 머리글 거리·셀 x범위·코드/금액/날짜 타입·여러 행의 반복·유효한 산식 근거를 함께 본다. 기존 열 맞바꿈 규칙을 확장할 때 후보 배정의 근거와 차이가 충분한 경우만 적용하고 동률은 검토한다. 근거 없는 대규모 일반 최적화나 모든 열 순열 탐색은 초기 실험에서 하지 않는다.

산식은 오류 검출에 사용하고 합계를 맞추려고 인쇄 금액을 바꾸지 않는다. 전체 합계 범위와 소계 포함 여부가 확인된 경우만 비교한다. 분류·날짜 이어 채우기는 현재 구현을 유지하고 소계·새 섹션·표 종료에서 끊기는지 회귀 검증한다.

## 6 재판독 단위를 필드나 표 전체에서 의심 행 묶음으로 조정

누락·열 이동·문자 오독을 구분해 필요한 영역을 선택한다. 금액 한 칸의 오독이면 해당 행과 머리글, 열 의미 불확실이면 머리글과 몇 개 대표 행 또는 표 전체, 여러 쪽 연결 문제면 양쪽 경계만 제공한다. 동일 영역의 여러 의심 칸은 한 요청으로 묶는다.

현재 일부 leaf ROI 재처리는 있으므로 새 실험은 첫 추출의 문제 행 탐지와 행 단위 묶음 재판독이다. 원문 행 ID가 같은 결과만 부분 반영하고 무관한 정답 행은 그대로 유지한다. 산식 하나나 모델의 확신 표현만으로 채택하지 않는다. 영역이 좁아도 실패하는 사례에서는 넓은 영역으로 예산 내 확장한다.

전체 재추출 대비 최종 정확도, 교정으로 망친 칸, ROI 호출수와 전체 시간, p95를 비교한다. 호출만 빨라지고 탐지 recall이 떨어진 결과는 개선으로 판정하지 않는다.

## 전처리의 범위

이미 구현된 90도 회전 보정 외에 작은 기울기는 OCR 줄 기준선이나 표 가로선의 Hough 추정으로 보정하는 가설을 둔다. 본문 글자·선의 다수 근거가 일치할 때만 적용하고 좌표 변환을 기록한다. 촬영 문서는 사각형 경계 근거가 충분할 때 원근 보정을 별도 실험한다.

원본·기울기 보정·필요 시 대비 조정 결과를 같은 모델로 비교한다. 모든 문서의 이진화·샤프닝·선 제거는 기본안으로 두지 않는다. 소수점·얇은 숫자·표 구조 손실을 따로 측정한다. 비가시 내용을 복원하는 생성형 업스케일은 이 제안에 포함하지 않는다.

## 실험 순서

### 액션 아이템

아래는 실행할 작업 목록이며 구현·실험 완료를 뜻하지 않는다. 모델·가중치는 고정한다. 코드 작업은 각 저장소 dev에서 새 브랜치와 worktree로 진행한다. 기존 0~6번을 유지하고 1a·1b·5a로 근거 검증·오류 분류·교정 재검증을 보강했다. 이미 있는 `groundings`·`field_quality`·규칙·마스터·재처리 예산을 재사용하며 별도 중복 판정기나 무제한 agent loop를 추가하지 않는다.

| 순서 | 작업 | 산출물 | 판정 기준 |
|---|---|---|---|
| 0 | 기준 커밋·설정·검수 데이터·지표·호출 예산 동결 | manifest, 현행 값·행 완결성·근거·지연 보고서 | 회귀셋과 새 홀드아웃 분리. 품질 허용 범위와 문서당 재처리 예산을 실험 전에 기록 |
| 1 | 원문 행 목록과 출력 행 대응 검사 | 누락·중복·미대응 위치 목록, 오프라인 평가 | 행 누락 탐지 recall·오탐률 및 원문 행 목록 자체 오류 측정. 반복 항목 보존 |
| 1a | 필드·셀의 근거 보존과 값·위치·역할 검증 | 기존 근거의 공통 평가 표현, 검증 판정·사유·근거 커버리지 | 같은 값의 다른 셀, 잘못된 라벨·열, 없는/잘린 근거를 구분. 값 정답률과 근거 정답률을 분리 |
| 1b | 실패 원인 분류와 처리 경로 정의 | 오류 코드·원문 위치·대상 경로·선택 도구·우선순위 표 | 누락·문자 오독·행/열 이동·형식·논리·근거 부족을 구분. 분류 모호성·복합 오류를 유지하고 분류 품질을 검수 |
| 2 | 레이아웃 보존 입력 A/B | 현행/열 정렬/머리글 계층+행 배열 입력과 결과 | 금액·코드·열 배정 정확도, 입력·출력 토큰, 전체 지연 비교 |
| 3 | 첫 추출의 문맥 포함 표 크롭 A/B | 전체 페이지/표 크롭/전체 축소+크롭 결과 | 작은 숫자 정확도·문맥 손실·시각 토큰·전체 지연 비교 |
| 4 | 단일 페이지의 긴 표를 행 묶음으로 분할 | 머리글·분류 문맥을 포함한 분할·원문 위치 기반 병합 | JSON 실패·잘림·경계 누락·중복 감소, 정상 반복 행 보존 |
| 5 | 오류 유형별 도구로 문제 행 묶음만 처리 | 규칙/마스터·행/셀 재탐색·ROI 판독의 고정 라우팅과 후보 부분 반영 | 전체 재추출 대비 최종 정확도·호출수·p95 비교. 근거 부족·예산 소진은 검토로 남김 |
| 5a | 교정 후보를 독립 근거로 재검증하고 채택·보류 | 이전값·후보값·원문 근거·검증 항목·최종 채택 사유 | 값·위치·역할·완결성과 영향받는 규칙을 재검사. 새로 망친 정답·미해결 오류·무관한 행 변경을 기록 |
| 6 | 자동 적재 게이트와 통합 홀드아웃 평가 | 값/근거/완결성 지표, 적재 비율별 오류율·지연·비용, 채택/보류 보고서 | 전체 결과 품질과 자동 적재 집합의 오류율을 각각 보고. 낮은 처리율로 품질을 높인 효과를 분리하고 문서 단위 불확실성을 제시 |

0 이후 1·1a의 오프라인 평가를 먼저 수행하고 오류 목록으로 1b를 만든다. 2·3은 독립 A/B로 수행하며 결과를 무조건 함께 적용하지 않는다. 4의 병합은 1의 원문 행 식별을 활용한다. 5는 1·1a·1b의 탐지와 3의 ROI 검증 결과를 사용하며 5a의 채택 검사를 항상 거친다. 실제 조밀한 표 실패가 확인되면 4도 우선 진행한다. 모든 실험 조합을 전량 실행하지 않는다.

후순위는 작은 기울기·원근 보정, 문서 내부 서식 변경 구간 분리, 페이지 경계에서 잘린 항목 연결이다. 해당 오류가 실제 평가셋에 확인된 경우 추가한다. 모델 교체와 전체 문서의 무조건 이진화·샤프닝은 현재 범위에서 제외한다.

### 근거 검증의 산출물

추가 코드 검토에서 기존 harness dev의 `reread/quality.py::quality_accepted`는 값·역할·좌표를 포함한 provenance 구조를 검사하고, `pipeline/runner.py::_resolved_by`는 교정 후 규칙 실패의 변화를 검사함을 확인했다. 1a·5a는 이 경로의 공백과 효과를 평가하며 중복 구현하지 않는다. `reread/docraft.py`의 scalar 근거 공유 검사 `_drop_shared_evidence`는 표 셀 근거가 추가되기 전에 호출된다. 따라서 표 셀에서도 동일 값의 근거 충돌을 검사할 필요가 있는지 별도 감사한다. 해당 호출 순서만으로 실제 오추출이 발생했다고 단정하지 않는다.

모든 요청 필드·셀에 근거 또는 근거 없음 상태를 표현한다. 기존 응답을 공통 평가 형식으로 옮기며 외부 출력 스키마 변경은 별도 구현 범위로 둔다. 공통 평가에는 값과 raw 값, field path, 페이지·원문 영역 또는 토큰/행/셀 ID, 원문 text, 라벨·열 역할, 좌표 변환, 근거 출처, 검증 상태·사유를 포함한다. 빈칸·미인쇄·판독 불가·파생값은 구분하고 근거가 없는데 bbox를 생성해 채우지 않는다. 파생값은 인쇄값으로 취급하지 않고 사용한 항과 규칙의 근거를 보존한다.

검증은 ① 원문에 값이 있는가 ② 표시한 영역·행·셀에서 읽혔는가 ③ 해당 라벨·열의 값인가로 나누고 각 축의 pass/fail/unavailable과 근거 의존성을 기록한다. 위치 정답이 필요한 표본에는 사람 검수 위치·역할 근거를 추가한다. 값 정답지만으로 bbox 정확도를 평가하지 않는다. 서로 다른 필드가 같은 셀을 정상 공유하는 경우는 허용하고 단순 bbox 겹침을 오류로 판정하지 않는다. 서로 다른 열이 같은 숫자를 갖는 경우에는 역할·위치 근거로 구분하며 표 셀의 잘못된 근거 재사용을 별도 회귀로 둔다.

기존 저장 응답의 근거만으로 1a를 시작한다. AO 응답에 근거가 없는 부분은 coverage로 보고하며, 이를 채우기 위한 추가 OCR·VLM 호출은 별도 실험으로 집계한다. 근거가 있는 의심 필드만의 점수를 전체 필드 점수로 해석하지 않는다.

### 오류별 처리와 교정 채택

| 오류 유형 | 우선 처리 | 채택에 필요한 확인 |
|---|---|---|
| 출력 행·셀 누락 | 원문 대비 탐색 후 누락 영역 판독 | 원문 행 존재·역할, 중복 없음, 경계와 인쇄 열 보존 |
| 숫자·코드 문자 오독 | 해당 행과 머리글의 ROI 판독 | 후보 문자가 실제 원문에 있고 해당 필드에 속함 |
| 행·열·셀 이동 | 위치·머리글 재탐색, 모호하면 관련 표 판독 | 값뿐 아니라 대상 행·열 역할 확인. 모호한 같은 값은 확정하지 않음 |
| 날짜·숫자·코드 형식 | 근거 있는 결정적 정규화 | raw 값 보존, 소수점·음수·정상 코드의 의미 변화 없음 |
| 합계·마스터 불일치 | 적용 범위·단위·키 확인 후 관련 칸 탐색 | 규칙/마스터의 적용 근거 확인. 원문을 산식·마스터에 맞춰 덮어쓰지 않음 |
| 근거 부족·복합 또는 불명확 | 필요한 근거 수집 또는 검토 표시 | 증거 충돌을 숨기지 않고 예산 내에서만 추가 탐색 |

1b의 최초 분류는 규칙·좌표·기존 로그로 구성해 추가 분류 VLM 호출을 기본으로 넣지 않는다. 한 후보를 제안한 모델의 같은 답 반복만으로 검증 완료로 보지 않는다. 5a는 재사용 가능한 원문 문자·좌표·라벨·행 대응 및 적용 가능한 규칙을 먼저 확인한다. 같은 오류를 공유할 수 있는 OCR 근거의 한계도 기록한다.

교정 후보는 원문 행·필드 대응과 필요한 값·위치·역할 근거가 확인되고 해당 오류를 해소하며 새로운 hard-rule 실패를 만들지 않을 때 채택하는 기준을 평가한다. 행·열 교정은 관련 행·이웃 경계와 적용 범위가 확인된 소계/합계도 재검사한다. 교정 실패·근거 충돌은 이전 값과 후보를 함께 남기고 미해결 상태로 둔다. 문서당 도구 호출수·시간·반복 횟수의 상한, 같은 후보 반복·진전 없음·시한 종료의 중단 조건을 고정한다. 값 채택과 고객 자동 적재 가능 여부는 별도 결정이며, 최종 판정 책임은 기존 harness에 유지한다.

### 비교와 회귀 사례

비교군은 현행, 현행+오프라인 탐지/검증만, 현행+탐지/검증+선택적 교정, 현행+기존 전체 재추출로 나눈다. 동일 최초 추출 결과와 같은 문서 예산으로 비교하고 실제 외부 호출을 중복하지 않는다. 저장 응답 재생 비교와 새 판독 비교를 구분한다. 2·3은 별도의 입력 실험으로 유지한다.

회귀 사례에는 같은 금액의 서로 다른 열, 올바른 값과 잘못된 bbox, 근거 없는 값, 정상 근거 공유, 행 전체 누락, 반복 항목, 물리 빈칸/미인쇄/판독 불가, 분류 제목·소계·합계 경계, 여러 쪽 및 행 묶음 경계, 소수점·음수, 오적용 산식·마스터, 정답을 오답으로 바꾸는 교정, 예산·시한 소진을 포함한다. 기존 59건은 회귀 자료이며 새 검수 홀드아웃으로 일반화를 평가한다.

99% 목표는 전체 필드/표 칸 정확도인지 문서 완전 정답률인지 명시하고 자동 적재 필드 오류율과 구분한다. 게이트 문턱값은 튜닝셋에서 정하고 홀드아웃에서 고정한다. PASS 비율·그 집합의 오류율·전체 미해결률을 함께 보고한다. 표본이 작아 목표 오류율을 확인할 수 없으면 인증된 품질처럼 표현하지 않는다.

모델·가중치·추론 엔진·정밀도·출력 예산·동시성을 기록하고 각 실험에서 변경한 요소만 명시한다. 회전/촬영·조밀한 글자·병합·여러 쪽·반복 항목·소계/합계·미인쇄/빈칸·소수점/음수 사례를 포함한다. 정확도는 핵심 금액/코드·행 recall·문서 완전 정답률을, 지연은 단계별 시간과 전체 p50/p95·재호출·실패를 보고한다.

이번 작업은 설계·기록만 수행했다. 코드 변경·모델 실행·AWS 호출 없음. 향후 외부 실험은 기존 배포 담당 취합 규칙을 따른다.
