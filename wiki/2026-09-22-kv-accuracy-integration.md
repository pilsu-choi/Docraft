## 가산성 판단: 세 변경은 정확히 합산된다

| 브랜치 | 개별 보고 correct | 개별 보고 fp |
|---|---|---|
| row-align | 7173 → 7179 (+6) | 365 → 356 (−9) |
| fill-fp | 7173 → 7175 (+2) | 365 → 339 (−26) |
| master | 7173 → 7177 (+4) | 365 → 365 (0) |
| 합 | +12 | −35 |
| **통합 실측** | **7173 → 7185 (+12)** | **365 → 330 (−35)** |

정답 +12, 오탐 −35로 개별 델타의 단순 합과 한 건도 어긋나지 않는다. 세 변경이 건드리는 셀 집합이 겹치지 않기 때문이다 — row-align은 영수증 항목 행의 위치, fill-fp는 스칼라 라벨 보충, master는 코드가 맞는 행의 명칭 한 글자로 서로 다른 축을 고친다. 병합 순서나 `apply` 안의 단계 순서(`_fill` → `_receipt_table` → `_totals` → `derive` → `_master_names`)에서 생기는 상호작용은 이번 76건에서 관측되지 않았다.

채점 함수 `pair_rows`는 row-align에서 `scripts/verify_eval`이 갖고 있던 것이 `rules`로 옮겨갔고, 항목내역 키에 `시작일자`가 추가됐으므로, 기준선 7173은 옛 채점기, 통합 후 7185는 새 채점기로 잰 값이다. 세 브랜치의 개별 보고도 같은 기준선·같은 새 채점기를 썼으므로 위 비교는 일관되며, 채점 변경 자체의 기여는 세 델타에 이미 포함돼 있다. 즉 +12 중 채점 규칙 변경분과 룰 변경분을 더 쪼개려면 별도 측정이 필요하다.

## holdout에서 거의 변화가 없다는 것의 의미

홀드아웃 40건의 개선은 정답 +2, strict 0, fp −11에 그쳤고, 전체 개선 +12 중 10건이 기존 36건에 몰렸다. 기존 36건은 앞선 작업들이 오류 사례를 직접 보고 고쳐 온 집합이므로, 이번 세 변경 역시 그 집합의 실패 패턴(영수증 항목 행 밀림, 특정 라벨 오매핑, 이미 코드가 맞는 명칭)에 맞춰져 있다는 뜻이다. 일반화되는 이득은 대부분 오탐 감소 쪽이다(holdout fp −11: 진단서 −9, 소견서 −2). fill-fp의 영역 제약·상호배제는 문서 서식에 의존하지 않는 규칙이라 신규 문서에서도 오탐을 줄였지만, 정답을 새로 맞히는 데까지는 가지 못했다.

세부내역서가 기존 98.3% 대 신규 74.9%로 갈리는 격차는 이번 병합으로 전혀 좁혀지지 않았다. 남은 오류가 룰 계층이 아니라 그 앞 단계에 있다는 신호다.

## 남은 오류의 주요 원인

1. **모델 추출 결과가 인쇄된 표와 다르다.** 세부내역서 `투여량` 69건, `단가` 79건은 열이 통째로 밀리거나 인접 열 값이 들어온 경우다. 특히 `단가` fp 39는 raw 단계에서도 같은 수로, 룰 파생이 아니라 모델 추출 단계의 오탐이다(이 점은 [kv-accuracy-review](2026-09-22-kv-accuracy-review.md)의 원인 설명을 이번에 바로잡았다).
2. **OCR 글자 오인식은 사전으로 한 자릿수만 고칠 수 있다.** EDI명칭 오류 128건 중 마스터 교정이 실제로 되돌린 것은 코드가 마스터에 적중하면서 명칭이 1글자만 어긋난 행뿐이다. EDI코드 미적중률이 28%(원내코드 혼입)라 사전을 더 공격적으로 쓰면(명칭 통째 대체) 순손실 −13으로 오히려 나빠진다([master-name-correction](2026-09-22-master-name-correction.md)의 임계값 스윕).
3. **파서 표 복원 실패.** `_receipt_table`은 파서 표가 항목명 중복 없이 넉넉히 복원됐을 때만 뼈대로 쓴다. 괘선이 약하거나 병합 셀이 뭉개져 복원이 부실한 문서에서는 예전처럼 빠진 행만 끼워 넣는 경로로 떨어지고, 행 밀림이 그대로 남는다.
4. **정답셋 라벨 오류.** 예: `세부내역서/3022033117174302-1.png`의 `시작일자`가 라벨 전체에서 `20020226`으로 적혀 있다(50회). 2002년 진료일은 문서 맥락상 있을 수 없고 `20200226`이 맞다. 이런 라벨은 아무리 고쳐도 오답으로 집계되므로 측정 상한을 깎는다.

## 다음 단계 제안

1. 홀드아웃 세부내역서 10건의 열 밀림 사례를 원문과 대조해, 원인이 추출 프롬프트인지 표 복원인지 가른다. 현재 룰 계층에서 더 짜낼 여지는 작다.
2. 파서 표 복원 품질을 지표로 남긴다(`_receipt_rows`가 뼈대로 채택됐는지 여부를 평가 산출물에 기록). 채택률과 정확도의 상관을 보면 3번 원인의 크기를 잴 수 있다.
3. 라벨 검수 2차: 신규 40건 silver에서 날짜·전화번호·판독 불가 문구가 값에 섞인 사례를 훑는다. 최소한 `3022033117174302-1`의 `시작일자`는 고친다.
4. 검토 문서 우선순위 4번(비교·Judge 정밀화)으로 넘어간다. 영수증의 관용 91.7% 대 strict 76.8% 격차는 `rules.same`의 부분 포함 관용에서 나오므로, 여기를 조이면 실제 품질과 측정치가 가까워진다.
