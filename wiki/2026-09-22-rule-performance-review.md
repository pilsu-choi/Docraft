# 룰 검증 성능 개선 우선순위

2026-09-22 · 브랜치 `docs/rule-performance-review` · 워크트리 `.worktrees/rule-performance-review`

## 근거와 범위

기준 코드: main `b676639`. 코드 탐색은 경량 서브에이전트와 병렬 검토했다. 이번 작업은 제안과 문서화이며 실행 코드를 변경하거나 모델·OCR를 재실행하지 않았다.

저장된 `data/verify/eval-20260922-164129.json`의 raw/rules 평가(36건)에서 룰 적용 후 정확도는 진단서 117/133(88.0%), 소견서 118/145(81.4%), 진료비영수증 877/1039(84.4%), 세부내역서 2126/2169(98.0%)다. 이는 순수 룰 추출 성능이 아니라 모델 추출 후 룰 후처리 성능이다. final 평가 자료는 gold 4건에 한정되어 일반화 근거가 부족하다.

같은 파일의 rules 단계 오류 목록(오답과 오탐 포함)에서 진료비영수증 `항목내역.항목` 119건이 가장 많다. 기존 계획의 240건은 이 단일 단계 집계와 같지 않으므로 그대로 개선 기준으로 쓰지 않는다. 현 평가의 correct/total은 빈 정답에 값을 채운 오탐을 분모에 포함하지 않아 fp를 반드시 함께 봐야 한다.

## 사용자 목표: 정확도 96% 우선

추가 지시로 1차 목표는 속도가 아니라 정확도 96% 달성으로 정했다. 96%의 적용 단계(룰 적용 결과/최종 Judge 결과)와 집계 단위는 질문한 상태다. 아래는 권장 기준인 **문서 유형별 룰 적용 결과 96%**의 격차 분석이며 확정 요구사항은 아니다. 정확도 유지가 확인되기 전 모델 호출 제거는 보류한다.

| 유형 | 현재 rules | 고정된 현재 분모에서 96%까지 필요한 추가 정답 |
|---|---:|---:|
| 진단서 | 88.0% | 11/133 |
| 소견서 | 81.4% | 22/145 |
| 진료비영수증 | 84.4% | 121/1039 |
| 세부내역서 | 98.0% | 이미 충족, 오탐 56건 별도 개선 |

영수증 항목명 오답 119건을 전부 해결해도 고정 분모에서 996/1039=95.9%여서 다른 필드도 개선해야 한다. 소견서는 치료명 8건·검사명 4건·병명 3건의 오답이 주요 대상이다. 정규식·동의어만으로 의미 추출을 해결할 수 있다고 가정하지 말고 원문 문장 보존과 필요한 모델 추출을 함께 검토한다. 실제 행 대응이 바뀌면 채점도 다시 수행해야 한다.

개선 후 기존 36건 회귀 평가와 별도 서식 검증을 통과한 결과로 달성 여부를 판단한다. 점수를 올리려고 비교 조건을 느슨하게 바꾸거나 정답셋을 예측에 맞추는 방식은 제외한다.

## 제안

| 순서 | 변경 | 코드 근거와 기대 효과 |
|---|---|---|
| 1 | 영수증 표 행·열 복원 | `rules.apply`는 모델 결과 후처리다. 파싱 `rows`와 `spans`에서 다단 머리글을 매핑하고 빈 금액 행도 보존해 누락 항목을 복원한다. 파싱 자체가 행을 잃었으면 이미지 재확인이 필요하다. |
| 2 | 필드별 자동 일치 기준 | `rules.same`은 4글자 이상 텍스트 부분 포함, 금액·수량의 빈 값과 0을 일치로 취급한다. 병명·주소 등 의미가 달라질 수 있는 필드는 엄격 비교하고, 빈 셀과 추출 실패를 구분한다. 원문을 보존하고 명시적으로 허용한 표기 차이만 정규화한다. |
| 3 | 행 정렬 후 셀 단위 Judge | `verify._rows_same`은 행 순서로 비교하며, 한 셀만 달라도 표 전체가 disputes에 들어간다. 항목·EDI코드·날짜와 중복 발생 순서를 이용해 행을 대응시키고, 의심 셀·인접 행·머리글을 Judge에 보낸다. 대응이 모호하거나 행이 누락된 표는 전체 문맥을 유지한다. |
| 4 | 유형별 제약 검사 확장 | `rules.check`는 진료비영수증 전용이다. 세부내역서의 단가×수량×횟수 관계는 해당 양식의 산식이 확인된 경우 검사하고, 날짜 선후 관계 등도 추가한다. 반올림·할인·예외를 고려해 이상 검출과 자동 교정을 구분한다. |
| 5 | 환자·의료기관 영역 구분 | `_fill`의 동의어를 늘리기 전에 제목·주변 라벨·좌표로 영역을 식별한다. 주소·성명·전화처럼 같은 라벨을 공유하는 필드의 오탐을 줄이고, 동률 후보는 자동 보충하지 않는다. |

## 지연 개선

현재 `verify.run`은 Parse → 모델 Extract → rules → Judge다. [기존 룰 1차 전환 계획](2026-09-22-verify-rule-first-plan.md)의 방향대로 룰 추출 커버리지가 확인된 유형부터 모델 Extract를 생략하는 실험을 권한다. 과거 기록의 Extract 10~30초는 절감 후보이며 이번 작업에서 재측정한 수치나 보장값은 아니다.

OCR 줄 인식과 TABLE_REFINE의 선택 실행은 각각 끈 경우의 정확도와 지연을 별도로 비교한 뒤 결정한다. 순수 룰 CPU 최적화나 GPU 증설보다 호출 경로와 Judge 입력 범위를 먼저 개선한다.

## 평가와 적용 순서

1. 기존 오류 목록을 원문 대조해 누락 행·열 혼동·라벨 혼동·과도한 일치로 분류하고 회귀 사례를 고정한다.
2. 표 복원과 일치 기준 개선을 각각 적용해 효과를 분리 측정한다. 공통 비교 함수를 사용하더라도 운영의 느슨한 비교만으로 채점하지 않고 엄격 정규화 일치도 함께 보고한다.
3. 유형별 정확도, 오탐, 오류 검출 precision/recall, `agree_wrong`(자동 일치 확정 중 정답과 다른 비율), Judge 호출률·입력량, 단계별 지연과 p50/p95를 기록한다.
4. 36건은 개발·회귀용으로 사용하고 병원/서식 단위로 분리한 추가 검증셋에서 효과를 확인한다. 소수 gold 문서의 결과를 전체 성능으로 해석하지 않는다.
5. 품질 유지가 확인된 유형부터 룰 1차 추출과 선택적 Judge를 적용한다. 모호한 후보는 확인 대상으로 남긴다.
