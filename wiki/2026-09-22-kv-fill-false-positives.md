# 라벨 보충(_fill) 오탐 억제

2026-09-22 · 브랜치 `feat/kv-fill-fp` · 워크트리 `.worktrees/kv-fill-fp`

[key-value 추출 정확도 개선 지점 검토](2026-09-22-kv-accuracy-review.md)의 우선순위 2를 구현했다.
캐시(`data/verify/accuracy-20260922/pipeline-cache`)만 써서 모델·OCR 재실행 없이 측정했다.

## 문제

`rules._fill`은 빠진 스칼라를 라벨 동의어로 찾을 때 **문서 전체에서 첫 후보**를 채웠다.
`LABELS`의 "성명"·"주소"·"전화번호"는 환자 칸과 의료기관 칸이 나눠 쓰는데 `DISTINCT`는 주소·연락처 짝만
막았고, 값이 서로 다르게 정규화되면 그 방어도 뚫렸다. 기준선에서 `_fill`은 정답 182건을 채우는 대신
오탐 45건·오답 119건을 만들었고, raw→rules 신규 오탐 53건 중 대부분이 이 유형이었다.

- 진단서 `주소` fp 10 — 서식 아래쪽 의료기관 주소가 환자 주소 칸으로
- 진단서 `의사명` fp 5 — `[ ▣ ] 의사 [ ] 치과의사 [ ] 한의사 면허번호 제` 선택지 줄에서 "치과"
- 소견서 `주소` fp 6 — `및 명칭 :`·`연 령 M6743C` 같은 라벨 조각
- 진료비영수증 `환자정보-질병군(DRG)번호` — 서식 항목 번호가 붙은 라벨 "4 환자구분"
- 세부내역서 `환자정보(진료종료일)` — 시작일·종료일이 같은 라벨 "진료기간"을 써서 둘 다 첫 날짜

## 바꾼 것 (`backend/rules.py`)

| 함수 | 변경 |
|---|---|
| `EXCLUSIVE`·`_exclusive` | `DISTINCT`(주소·연락처 짝)를 필드 무리로 일반화. 주소류·연락처류·이름류·날짜류·진료기간 5무리. 한 무리 안에서 한 값은 한 필드만 쓴다 |
| `SECTIONS`·`FIELD_SECTION`·`_section` | 블록·행을 순서대로 지나며 지금 칸이 환자 칸인지 의료기관 칸인지 기억한다. 같은 라벨을 나눠 쓰는 필드는 제 영역 후보만 받고, 영역이 정해지지 않으면 채우지 않는다 |
| `_matches` | bool → 근거 등급(라벨과 똑같은 셀 0, 라벨로 시작하는 셀 1). 텍스트 줄은 2 |
| `_candidates` | `(등급, 영역, 값)`을 낸다. 값이 없는 라벨 칸도 등급만 알린다 |
| `_fill` | 최선 등급에서만 고르고, ①그 등급 값이 갈리면 ②더 확실한 라벨 칸이 있는데 비어 있으면 ③같은 무리가 이미 쓰는 값이면 채우지 않는다 |
| `_picked` | `LAST_DATE`(진료종료일)는 "진료기간 A ~ B" 한 칸에서 마지막 날짜를 취한다 |
| `EXPLICIT` | 소견서 `진단일`·`초진일`처럼 그 유형에 원래 드문 필드는 제 이름이 든 라벨일 때만 채운다 |
| `_junk` | 선택지 표시가 둘 이상인 문자열(`[ ] 의사 [ ] 치과의사`)과 서식 항목 번호가 앞에 붙은 라벨("4 환자구분")을 라벨 글자로 본다 |
| `_name`·`_address`·`_key` | 이름에서 "연령"·"나이"를 지우고 성별 보기 칸(남/여)을 버린다. 주소는 한글 지명 두 글자를 요구한다. 라벨 비교에서 표 구분자 `|`를 지운다 |

## 하지 않은 것과 근거

- **세부내역서 `단가` 파생(fp 39)은 존재하지 않는다.** raw 단계 fp와 rules 단계 fp가 39로 같고
  `backend/`에 단가를 총액·수량으로 계산하는 코드가 없다. 모델 추출 단계의 오탐이므로 룰에서 고칠 것이 없다.
- **`_columns`의 라벨 없는 파생(세부내역서 종료일자←시작일자, 급여/비급여←총액)은 유지한다.**
  꺼 보니 correct 7175 → 7098(-77), fp 339 → 339(변화 없음). 순손실이라 되돌렸다.
- **`_notes`의 소견 문장 → 치료내역 행(fp 10)도 유지한다.** 꺼 보니 fp 339 → 329(-10),
  correct 7175 → 7172(-3). 라벨("치료소견" 등) 근거가 분명한 보충이고 정답을 잃어 손대지 않았다.
- `rules.same`·정답 라벨·매니페스트는 건드리지 않았다.

## 남은 오탐의 원인

rules가 새로 만드는 오탐 27건 중 `치료내역.치료명` 10건은 위의 라벨 관례 차이,
`항목내역.본인부담금`·`공단부담금` 각 3건은 영수증 표 행 복원(`_receipt_table`) 몫이다.
`_fill`에 남은 18건은 표 구조가 무너진 파싱 결과(값이 여러 열에 되풀이되는 소견서)나
정답 라벨 쪽 누락이 섞여 있어 룰만으로는 가르기 어렵다. 전체 fp 339 중 절대다수는 모델 추출 단계의
것이고(raw 459), 특히 세부내역서 `단가`·`투여량`은 열 밀림 문제라 우선순위 1·4에서 다룬다.
