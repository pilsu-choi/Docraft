## 범위와 가정

이 문서는 설계·테스트용 예상 시나리오다. 현재 제품에서 재현한 결함 목록이 아니다.

- Parse: 이미지를 읽어 텍스트, 표, 읽기 순서, 페이지와 위치 정보를 복원한다.
- Extract: 이미지 또는 Parse 결과에서 스키마의 필드·배열에 값을 연결하고 정규화한다.
- 이미지에는 스캔, 휴대폰 촬영, 캡처, PDF를 렌더링한 페이지를 포함한다. 숨겨진 텍스트 레이어의 정확성은 가정하지 않는다.
- Extract가 이미지를 직접 보는 방식도 동일한 시각 인식 오류를 겪을 수 있다. 이 경우 Parse 오류와 Extract 오류가 내부적으로 합쳐져 드러난다.
- 의료 문서 예시는 추출 설계를 위한 것이며, 임상 판단이나 실제 개인정보를 포함하지 않는다.

## Parse: 무엇을 어떻게 읽었는가

| 구분 | 엣지 케이스 | 예상 오류 | 처리·검증 기준 |
| --- | --- | --- | --- |
| 화질 | 저해상도, 흔들림, 압축, 흐린 팩스 | 소수점·음수·글자 획 소실 | 원본 및 영역 확대 확인. 없는 획을 복원했다고 확정하지 않기 |
| 촬영 | 회전, 기울기, 원근 왜곡, 접힘, 곡면 | 줄·열 경계와 읽기 순서 왜곡 | 방향·왜곡 보정 후 좌표를 원본 이미지로 환산 |
| 가림·잘림 | 반사광, 그림자, 손가락, 도장, 페이지 가장자리 잘림 | 이름·금액 일부 누락 | 누락 영역을 표시하고 재촬영 또는 검토로 연결 |
| 전처리 | 과한 이진화·노이즈 제거·리사이즈 | 연한 글씨, 체크 표시, 소수점 삭제 | 원본을 보존하고 전처리 전후 정보 손실 확인 |
| 문자 혼동 | 0/O, 1/I/l, 5/S, 한글 유사 글자, 혼합 언어 | 코드·식별자·숫자 오인 | 원문 표기와 후보 보존. 문맥만으로 확정하지 않기 |
| 필기·수정 | 손글씨, 취소선, 덧쓰기, 인쇄값 옆 수정값 | 폐기된 값 채택, 두 값을 합침 | 기존값·수정값·취소 표시의 관계 보존 |
| 읽기 순서 | 다단 문서, 측면 메모, 세로쓰기, 각주 | 서로 다른 문단 또는 필드 연결 | 텍스트 순서 외에 영역·위치 관계 보존 |
| 표 구조 | 병합 셀, 무테 표, 줄바꿈 셀, 빈 셀 | 금액이 옆 열로 이동, 한 행이 두 행으로 분리 | 행·열·헤더 대응 검증. 빈 셀 때문에 열을 당기지 않기 |
| 표 연속성 | 다음 페이지로 이어진 표, 반복 헤더, 행 중간 페이지 분리 | 중복 행·누락 행·잘못된 이어 붙이기 | 연속 표 여부와 헤더를 확인하고 원래 페이지 유지 |
| 비문자 표시 | 체크박스, 동그라미, 화살표, 음영, 도장 | 선택 여부와 관계 정보 소실 | 표시 상태를 별도로 읽고 글자와의 연결 확인 |
| 문서 경계 | 한 사진에 영수증 두 장, 앞뒷면, 빈 페이지, 중복 스캔 | 문서 혼합, 페이지 누락·중복 | 페이지 경계와 논리 문서 경계를 구분 |
| 큰 입력 | 긴 영수증, 초고해상도 이미지, 작은 글씨가 많은 페이지 | 축소로 글자 소실, 타일 경계 누락·중복 | 겹치는 영역으로 분할하고 좌표·중복 병합 검증 |
| 이미지 디코딩 | EXIF 회전, 투명 배경, 다중 프레임 TIFF, 손상 파일 | 거꾸로 읽기, 검은 배경, 첫 프레임만 처리 | 디코딩 결과·프레임 수·방향 확인, 실패를 빈 문서로 처리하지 않기 |
| 출력 완결성 | 긴 출력의 중단, 일부 영역만 인식 | 문법은 유효하지만 내용이 불완전 | 페이지·영역 처리 범위와 완료 상태를 결과와 함께 관리 |

## Extract: 읽은 내용을 어떤 필드에 넣었는가

| 구분 | 엣지 케이스 | 예상 오류 | 처리·검증 기준 |
| --- | --- | --- | --- |
| 대상 귀속 | 환자·보호자·계약자·의사 이름 공존 | 정확히 읽은 이름을 잘못된 사람에게 연결 | 라벨, 영역, 문서 단위로 대상 연결 |
| 날짜 역할 | 진료일·입원일·퇴원일·발행일·결제일 공존 | 형식은 맞지만 의미가 다른 날짜 채택 | 필드 정의에 날짜 역할 명시, 후보와 근거 보존 |
| 금액 역할 | 총액·본인부담·공단부담·수납·미수·환불 공존 | 잘 보이는 합계를 청구 대상 금액으로 선택 | 필드 정의와 표 헤더로 연결. 계산식은 서식별 적용 조건 확인 |
| 부정·불확실성 | 없음, 의심, 배제 필요, 과거력, 가족력 | 언급된 질환·수술을 확정 사실로 추출 | 부정·확실성·시점·대상 함께 해석 |
| 결측 의미 | 빈칸, 미기재, 판독불가, 해당 없음, 0, 대시 | 모두 null 또는 0으로 축약 | 값과 추출 상태를 분리. 대시 의미는 서식 정책으로 결정 |
| 복수 값 | 여러 진단·수술·방문·영수증, 여러 후보 날짜 | 첫 항목만 추출, 임의로 하나 선택 | 배열 및 단일값 선택 기준 정의, 불명확하면 충돌 표시 |
| 행 관계 | 항목·수량·단가·금액의 줄바꿈 또는 병합 | 서로 다른 행의 값으로 한 항목 생성 | 항목 단위 연결 및 행별 근거 유지 |
| 정정·재발행 | 원본과 정정본, 취소 영수증과 새 영수증 | 구버전 채택 또는 이중 집계 | 문서 관계·취소 상태 확인, 발행일만으로 우선순위 단정 금지 |
| 단위·형식 | 원/천원, mg/g, 괄호 음수, 로캘별 숫자, 불완전 날짜 | 배수·부호 오류, 없는 연도 생성 | 원문·정규값·단위 보존, 명시 근거 없는 보완 금지 |
| 식별자 | 선행 0, 하이픈, 마스킹된 번호 | 숫자 변환으로 0 소실, 가린 부분 추정 | 문자열로 보존, 마스킹 부분 복원 금지 |
| 상충 근거 | 본문과 표의 날짜·금액 불일치, 코드와 병명 불일치 | 그럴듯한 값으로 임의 교정 | 후보와 충돌을 노출하고 필요한 검토로 연결 |
| 스키마 불일치 | 다른 서식 적용, 필드 없는 문서, 필수값 강제 | 존재하지 않는 값 생성 | 문서 적합성 확인. 필수 스키마와 실제 결측 상태 구분 |
| 페이지 통합 | 다음 페이지의 헤더 생략, 서로 다른 환자 문서 묶음 | 앞 페이지의 대상·단위를 잘못 전파 | 문서 경계 확인 후 문맥 전파, 페이지별 출처 유지 |
| 모델 지시 혼입 | 이미지에 명령문·답안 예시가 포함 | 문서의 문장을 추출 지시로 따름 | 이미지 문구를 데이터로 취급, 출력 스키마·허용 동작 검증 |
| 근거 불일치 | 값은 맞지만 위치·페이지가 다른 항목을 가리킴 | 검토자가 잘못된 근거로 승인 | 값과 원본 페이지·영역을 함께 검증 |
| 직렬화 | 잘린 JSON, 타입 오류, 중복 키, 배열 일부 누락 | API 실패 또는 조용한 데이터 손실 | 문법·스키마·내용 완결성을 각각 확인 |

## 공통 처리 원칙

1. 원본 이미지, 읽은 원문, 정규화한 값을 구분한다. 추출값과 계산값도 구분한다.
2. `0`, 미기재, 판독불가, 해당 없음, 값 충돌을 구분한다. 기존 스키마를 유지해야 한다면 별도의 상태·근거 메타데이터에 기록한다.
3. 필드와 배열 항목에 원본 페이지·영역을 연결한다. 회전·크롭·리사이즈 후에도 원본 좌표를 추적한다.
4. 일부 실패를 전체 성공이나 전체 빈값으로 숨기지 않는다. 성공한 페이지와 실패한 페이지, 필드별 상태를 전달한다.
5. 재시도와 페이지 병렬 처리에서도 원래 순서·문서 ID를 유지하고 결과 중복·다른 요청 결과 혼입을 막는다. 캐시 사용 시 이미지뿐 아니라 모델·전처리·스키마 버전도 구분한다.
6. 모델이 출력한 자신감만으로 자동 확정하지 않는다. 형식·근거·관계·계산 검증과 별도 평가 데이터로 검토 기준을 정한다.
7. 읽을 수 없는 내용을 추측해 채우지 않는다. 원본 확대, 재처리, 재촬영, 수동 검토 중 오류 원인에 맞는 경로를 선택한다.
8. 산술 불일치를 발견해도 인쇄된 금액을 합계에 맞춰 덮어쓰지 않는다. 할인·반올림·기납부 등 계산 조건을 확인하고 관측값과 검증 결과를 분리한다.

## 우선 테스트할 사례

아래 우선순위는 발생 빈도의 측정값이 아니라 잘못된 자동 처리의 영향을 기준으로 한 제안이다.

| 우선순위 | 입력 구성 | 확인할 결과 |
| --- | --- | --- |
| P0 | 서로 다른 환자의 문서를 한 묶음으로 입력 | 환자별 경계 유지, 이름·금액 혼합 없음 |
| P0 | 총액·본인부담·기납부·미수금이 함께 있는 영수증 | 요청한 금액 역할에 정확히 연결 |
| P0 | 0원, 빈칸, 대시, 흐려서 읽을 수 없는 금액 각각 | 네 상황을 정책에 따라 구별 |
| P0 | 의심·부정·과거력과 확정 진단이 함께 있는 문서 | 확정 여부·시점·대상 혼동 없음 |
| P0 | 페이지를 넘는 표 + 반복 헤더 + 중간 빈 셀 | 행 누락·중복·열 밀림 없음 |
| P0 | 정정본·취소본·중복 스캔 혼합 | 무조건 합산하지 않고 관계·상태를 보존 |
| P0 | 잘린 날짜·가린 번호·없는 필수 필드 | 없는 정보 생성 없이 결측 사유 표시 |
| P1 | 회전·크롭·원근 보정이 필요한 이미지 | 필드 근거가 원본의 올바른 위치를 가리킴 |
| P1 | 긴 이미지·다중 프레임·중간 페이지 실패 | 전체 처리 범위와 부분 실패 확인 가능 |
| P1 | 원문에 추출 지시와 충돌하는 명령문 삽입 | 문서 내용을 지시로 실행하지 않음 |

각 사례는 깨끗한 원본과 변형본을 짝지어 평가한다. 복합 오류도 별도로 만든다. 예: 회전된 다중 페이지 표에 작은 글씨와 빈 셀을 함께 배치한다.

평가는 문자 인식 정확도 외에 필드 의미 정확도, 대상 귀속, 표 행·열 연결, 배열 누락·중복, 결측 상태, 근거 위치, 부분 실패 보고를 확인한다. Parse 결과를 고정한 Extract 평가와 이미지부터 시작하는 전체 평가를 함께 수행하면 실패 단계를 구분하기 쉽다. 직접 이미지 추출 경로는 별도로 평가한다.

## 작성 근거

사용자의 이미지 기반 Parse·Extract 엣지 케이스 정리 요청에 따른 일반 설계 검토다. 특정 엔진의 성능·지원 범위·발생 빈도를 검증한 문서가 아니다.
