## 목적과 범위

문서 유형이나 처리 시스템과 무관하게 쓸 수 있는 Parse·Extract 오류 분류다. 구현된 오류 코드 목록이나 발생 빈도 통계는 아니다. Parse는 원문의 내용·위치·구조를 인식하고, Extract는 이를 업무 스키마의 필드·레코드에 배정한다. 이미지를 함께 보는 Extract는 문자 판독도 수행하므로 일부 기능이 겹친다.

이 분류의 목표는 **아직 발견하지 못한 사례가 와도 들어갈 칸이 이미 있는 것**이다. 그래서 노드를 관측 사례에서 모으지 않고, 출력이 정답과 달라질 수 있는 방식을 출력 구조에서 끌어냈다(아래 생성 틀). 관측 사례는 이 틀이 빠짐없이 덮는지 확인하는 근거로만 쓴다.

노드 이름은 일반 용어로 둔다. 특정 도메인의 사례, 관측 이슈 대응, 시스템별 기록 값은 적용 프로파일 문서에 둔다. 의료비 문서 적용은 [Parse·Extract 이슈 분류 의료비 문서 적용 프로파일](2026-10-03-parse-extract-taxonomy-medical-profile.md)을, 하네스·Docraft의 노드별 탐지·보정 장치와 빈 곳은 [이슈 유형별 보정 장치 대응표](2026-10-04-issue-taxonomy-correction-coverage.md)를 본다.

## 생성 틀: 출력 단위 × 차이 종류

출력은 단위가 겹겹이 쌓인 구조다. 정답 출력과 실제 출력의 차이는 반드시 **어느 단위에서, 어떤 종류로** 달라졌는지로 표현된다. 두 계층 구조의 차이는 단위의 삭제·삽입·내용 변경·이동·경계 변경·순서 변경·관계 변경·속성 변경으로 분해되고, 그 밖의 차이는 출력 규칙(계약) 위반뿐이기 때문이다. 이 조합이 분류의 전체 공간이고, 트리의 각 노드는 이 공간의 한 칸이다.

**단위:** 문자·토큰 / 비문자 표시(체크·도장·서식) / 값 / 필드 / 레코드(행) / 열 / 표·그룹·섹션 / 페이지 / 문서 / 묶음(한 건으로 함께 들어온 문서들)

| 차이 종류 | 뜻 | Parse 노드 | Extract 노드 |
|---|---|---|---|
| K1 빠짐 | 있어야 할 단위가 없음 | `P.MIS.*` | `E.MIS.TARGET`·`FIELD` |
| K2 더해짐 | 원문에 없거나, 중복이거나, 범위 밖인 단위가 있음 | `P.OVR.*`, `P.WRG.TYPE` | `E.OVR.*` |
| K3 내용 바뀜 | 단위는 맞는데 내용이 다름(판독·변환·일부 손실) | `P.WRG.READ`, `P.MIS.CHAR` | `E.WRG.READ`·`NORM`, `E.MIS.PART` |
| K4 자리 바뀜 | 다른 칸·역할·상위 단위에 놓이거나 병렬 대응이 어긋남 | `P.WRG.POS` | `E.WRG.ASSIGN`, `E.STR.GROUP`·`ARRAY` |
| K5 경계 바뀜 | 합쳐지거나 나뉨 | `P.STR.SPLIT`·`LINK`·`DOC` | `E.STR.SPLIT`·`COMPOSE` |
| K6 순서 바뀜 | 순서가 다름 | `P.WRG.ORDER` | `E.STR.ORDER` |
| K7 관계 바뀜 | 머리글·라벨·병합·상속·개체·버전 연결이 다름 | `P.STR.REL`·`HIER` | `E.WRG.CTX` |
| K8 속성 바뀜 | 선택·확실성·시점·주체·판독 가능 여부·처리 상태·값의 출처(원문·계산·참조)가 다름 | `P.WRG.STATE` | `E.WRG.ATTR`·`READ.3`·`HOLD`, `E.MIS.ABST`, `E.OVR.GEN.2` |
| K9 선택 바뀜 | 여러 후보 중 다른 것을 고름 | 없음(Parse는 후보를 고르지 않음) | `E.WRG.PICK` |
| K10 계약 위반 | 형식·스키마·값 제약·근거·완료·공개 규칙 위반 | `P.CON.*` | `E.CON.*` |

원인(왜 생겼나)은 차이 종류와 따로 기록한다. 최초 발생 단계(`P`·`E`·`AUX.*`)와 기록 축(발생 조건 등)이 원인을 맡는다.

### 노드가 없는 칸과 그 이유

| 칸 | 이유 |
|---|---|
| K1·K2 × 열 | 열 전체 누락·추가는 셀 단위 노드의 반복이다. `오류 패턴` 축의 일괄로 표시한다 |
| K1 × 문서 | 문서 누락은 모든 쪽 누락(`P.MIS.AREA.1`)이나 입력 열기 실패(`AUX.INPUT`)로 나타난다 |
| K2 × 비문자 표시 | 없는 체크를 있다고 보는 것은 상태 반전(`P.WRG.STATE.1`)과 같은 사건이다 |
| K3 × 필드 이상 | 내용은 문자·값에서만 바뀐다. 상위 단위의 내용 차이는 하위 차이의 집계다. 문서 유형이 바뀐 것은 `AUX.SCHEMA` |
| K4·K5 × 묶음, K6·K7 × 묶음 | 묶음은 최상위 단위라 경계·순서가 없다. 묶음 안 문서 사이 관계는 `E.WRG.CTX.4`·`E.CON.RANGE.4` |
| K6 × 문자·필드·열·문서 | 문자 순서 뒤바뀜은 판독 오류로 나타나고, 필드·열·문서 순서는 보통 계약상 의미가 없다. 계약이 순서를 정하면 `E.STR.ORDER.1`을 그 단위에 쓴다 |
| K9 × Parse | Parse는 후보를 고르지 않는다. 텍스트 층과 이미지 중 하나를 고른 것은 `AUX.INPUT` |
| K10 × 비문자 표시 | 표시는 출력될 때 값이 되므로 값 단위 K10으로 센다 |

### 새 사례를 넣는 절차

1. 정답 출력과 실제 출력을 비교해 차이가 난 **단위**와 **차이 종류**를 정한다.
2. 그 칸의 노드 중 분류 경계 규칙에 맞는 것을 고른다. 노드가 여럿이면 경계 규칙을 따르고, 규칙으로 정해지지 않으면 경계 규칙을 먼저 보완한다.
3. 칸에 노드가 없거나 정의에 맞는 노드가 없으면, 위 "노드가 없는 칸" 사유가 실제로 성립하는지 확인한다. 성립하지 않으면 그 칸 아래에 노드를 추가한다. 기존 ID는 바꾸지 않고, 같은 Depth 2 아래 새 Depth 3 약어나 Depth 4 번호를 이어 붙인다.
4. 원인은 최초 발생 단계와 기록 축으로 따로 남긴다.
5. 노드에 연결된 보정 장치가 이 사례를 덮는지 [보정 장치 대응표](2026-10-04-issue-taxonomy-correction-coverage.md)에서 확인한다. 덮지 못하면 사례 하나를 고치는 대신 그 칸의 일반 장치를 보완한다.

## Depth 정의와 라벨링 ID

| Depth | 기준 | 예시 | ID 표기 |
|---|---|---|---|
| 1 | 발생 단계 | Parse / Extract | `P` / `E` |
| 2 | 결과 오류 유형 | 미추출 / 오추출 / 과추출 / 구조 오류 / 계약 오류 | `MIS` / `WRG` / `OVR` / `STR` / `CON` |
| 3 | 세부 오류 유형 | 영역 누락 / 판독 오류 / 배정 오류 | 트리의 `[대괄호]` 약어 |
| 4 | 구체적인 발생 형태 | 페이지 누락 / 숫자 오인식 / 다른 열에 배정 | 트리 순서 번호 |

ID는 `<D1>.<D2>.<D3>.<D4>` 형식이다(예: `E.WRG.ASSIGN.2`). 이슈 라벨링과 집계 표기를 고정하기 위한 것이며 코드에 구현된 오류 코드가 아니다. 같은 단계와 상위 유형 안에서 여러 현상이 함께 발생할 수 있으므로 완전히 배타적인 분류로 간주하지 않는다. 합성 데이터 생성기(`synthetics/generator/edge_cases.yaml`)와 label_viewer 자동 분류기가 이 ID를 쓰므로 기존 ID는 바꾸지 않는다.

- **미추출·오추출·과추출:** 내용 단위(문자·값·레코드)가 빠졌는지, 틀렸는지, 원문에 없이 더해졌는지다.
- **구조 오류:** 내용은 있지만 단위 사이의 경계·관계·계층·순서를 잘못 복원한 것이다.
- **계약 오류:** 출력이 정해진 형식·스키마·값 제약·근거·완료·공개 규칙을 어긴 것이다.

## Parse 계층

```text
Parse [P]
├─ 미추출 [MIS]
│  ├─ 영역 누락 [AREA]
│  │  ├─ 1 페이지 누락
│  │  └─ 2 표·본문·서식 블록 누락
│  ├─ 구조 단위 누락 [UNIT]
│  │  ├─ 1 행·열·목록 항목 누락
│  │  └─ 2 셀·머리글·라벨 누락
│  ├─ 문자 누락 [CHAR]
│  │  ├─ 1 문자열 전체·일부 누락
│  │  └─ 2 숫자·소수점·부호·단위 누락
│  └─ 비문자 요소 누락 [MARK]
│     ├─ 1 선택 표시(체크·동그라미·칠함) 누락
│     ├─ 2 수정 표시(취소선·덧쓰기·화살표) 누락
│     ├─ 3 서명·도장·바코드·도형 등 비문자 요소 누락
│     └─ 4 글자 서식(색·굵기·음영·밑줄)이 담는 의미 누락
│
├─ 오추출 [WRG]
│  ├─ 판독 오류 [READ]
│  │  ├─ 1 문자·숫자 오인식
│  │  ├─ 2 소수점·부호·기호·구두점 오인식
│  │  ├─ 3 손글씨와 인쇄 글자 구분 실패
│  │  ├─ 4 띄어쓰기·단어 경계 오류(공백 삽입·삭제)
│  │  └─ 5 문자 코드 변형(전각·합성 문자·자모 분리·보이지 않는 문자·인코딩 깨짐)
│  ├─ 위치 배정 오류 [POS]
│  │  ├─ 1 글자·표시를 다른 행·셀·영역에 배정
│  │  └─ 2 잘못된 좌표·페이지에 배정
│  ├─ 읽기 순서 오류 [ORDER]
│  │  ├─ 1 행·블록·페이지 순서 뒤바뀜
│  │  ├─ 2 서로 다른 영역의 글자 혼합
│  │  └─ 3 다단·세로쓰기 읽기 방향 오류
│  ├─ 요소 유형 오인식 [TYPE]
│  │  ├─ 1 머리말·꼬리말·쪽 번호·워터마크를 본문으로 인식
│  │  └─ 2 제목·본문·표·캡션·서식 칸 유형 오분류
│  └─ 상태 인식 오류 [STATE]
│     ├─ 1 선택·취소 표시 상태 반전
│     ├─ 2 판독 불가를 빈칸으로 처리
│     └─ 3 판독 가능한 글자를 판독 불가로 처리(과보류)
│
├─ 과추출 [OVR]
│  ├─ 문자 오탐 [FALSE]
│  │  ├─ 1 잡음·도장·배경 무늬·선택 표시를 문자로 인식
│  │  └─ 2 보이지 않는 텍스트 층·뒷면 비침 글자를 내용으로 인식
│  ├─ 중복 인식 [DUP]
│  │  ├─ 1 같은 영역·행을 중복 인식
│  │  └─ 2 같은 글자·값을 중복 출력
│  └─ 근거 없는 내용 생성 [GEN]
│     ├─ 1 원문에 없는 문자·값 생성(빈칸을 값으로 채움 포함)
│     └─ 2 원문에 없는 행·셀·블록 생성
│
├─ 구조 오류 [STR]
│  ├─ 경계 복원 오류 [SPLIT]
│  │  ├─ 1 여러 행·셀·블록을 하나로 합침
│  │  └─ 2 한 행·셀·블록을 여러 개로 분리
│  ├─ 관계 복원 오류 [REL]
│  │  ├─ 1 병합 셀 범위 복원 실패
│  │  ├─ 2 다단 머리글 연결 실패
│  │  ├─ 3 라벨과 값 짝짓기 실패
│  │  └─ 4 표시·기존값·수정값 연결 실패
│  ├─ 계층 복원 오류 [HIER]
│  │  ├─ 1 제목·목록의 계층 수준 오류
│  │  ├─ 2 각주·캡션과 대상 연결 실패
│  │  └─ 3 중첩 표·표 안 서식 구조 복원 실패
│  ├─ 연결 오류 [LINK]
│  │  ├─ 1 별개 표·블록을 하나로 연결
│  │  └─ 2 페이지를 넘어 이어진 표·블록을 연결하지 못함
│  └─ 논리 문서 경계 오류 [DOC]
│     ├─ 1 서로 다른 문서를 하나로 합침
│     └─ 2 한 문서를 여러 문서로 분리
│
└─ 계약 오류 [CON]
   ├─ 형식 오류 [FMT]
   │  ├─ 1 출력 직렬화 형식 오류
   │  └─ 2 셀·좌표·병합 정보 불일치
   ├─ 근거 계약 오류 [EVID]
   │  └─ 1 계약상 필수 원문 위치 근거 누락
   └─ 완료 오류 [DONE]
      └─ 1 출력 중단·부분 처리의 완료 오표시
```

## Extract 계층

```text
Extract [E]
├─ 미추출 [MIS]
│  ├─ 추출 대상 누락 [TARGET]
│  │  ├─ 1 필요한 표·그룹·섹션 전체 누락
│  │  └─ 2 요약·집계 단위 누락
│  ├─ 레코드·필드 누락 [FIELD]
│  │  ├─ 1 레코드 전체 누락
│  │  └─ 2 필드 값 누락
│  ├─ 값 일부 누락 [PART]
│  │  ├─ 1 문자열 일부 잘림
│  │  ├─ 2 숫자·소수점·부호·단위 일부 소실
│  │  └─ 3 복수 값 필드에서 일부 값만 출력
│  └─ 과보류 [ABST]
│     ├─ 1 읽을 수 있는 값을 판독 불가로 보류
│     └─ 2 근거가 충분한 값을 검토 필요로 보류
│
├─ 오추출 [WRG]
│  ├─ 판독 오류 [READ]
│  │  ├─ 1 이미지에서 문자·숫자를 잘못 읽음
│  │  ├─ 2 원문 값을 옮기면서 원문과 다르게 변경
│  │  └─ 3 선택·취소 표시 상태를 잘못 읽음
│  ├─ 배정 오류 [ASSIGN]
│  │  ├─ 1 다른 필드·그룹에 배정
│  │  ├─ 2 다른 행·열에 배정
│  │  └─ 3 의미 역할(주체·시점·수량) 오배정
│  ├─ 문맥 연결 오류 [CTX]
│  │  ├─ 1 라벨·머리글 의미 연결 오류
│  │  ├─ 2 병합·상속 값 연결 오류
│  │  ├─ 3 페이지·섹션 경계 연결 오류
│  │  ├─ 4 다른 개체·사건의 값 연결
│  │  └─ 5 원본·정정본·취소본 관계 연결 실패
│  ├─ 해석·정규화 오류 [NORM]
│  │  ├─ 1 범주값·코드 체계·표기 관례 의미 오해
│  │  ├─ 2 날짜·숫자·단위·통화 변환 오류(계약이 허용한 계산의 결과 오류 포함)
│  │  ├─ 3 빈값·0·미표기·판독 불가 혼동
│  │  └─ 4 과정규화: 원문보다 정보가 줄거나 원문과 달라지는 변환
│  ├─ 사실 속성 해석 오류 [ATTR]
│  │  ├─ 1 확실성(부정·추정·확정·전언) 해석 오류
│  │  ├─ 2 시점(과거·현재·예정) 해석 오류
│  │  └─ 3 주체(당사자·제3자) 해석 오류
│  ├─ 후보 선택 오류 [PICK]
│  │  ├─ 1 복수 후보의 선택 기준 오적용
│  │  └─ 2 상충 근거를 임의로 해소해 값 확정
│  └─ 보류 누락 [HOLD]
│     ├─ 1 판독 불가·가림·훼손 구간을 추측해 확정값으로 출력
│     └─ 2 원문이 드러내는 결락·불완전(결번 쪽 등)을 정상·완전으로 표시
│
├─ 과추출 [OVR]
│  ├─ 근거 없는 내용 생성 [GEN]
│  │  ├─ 1 원문에 없는 값·레코드 생성
│  │  └─ 2 계산·추론한 값을 원문값처럼 출력
│  ├─ 중복 출력 [DUP]
│  │  ├─ 1 같은 원문 항목을 여러 레코드로 출력
│  │  ├─ 2 같은 내용을 여러 필드에 불필요하게 복제
│  │  └─ 3 같은 문서·개체를 별도 건으로 중복 집계
│  └─ 범위 밖 내용 포함 [SCOPE]
│     ├─ 1 머리글·구분 제목을 레코드로 출력
│     ├─ 2 범위 밖 영역(주석·머리말·다른 문서)의 내용 포함
│     └─ 3 정책상 제외할 취소·구버전 내용 포함
│
├─ 구조 오류 [STR]
│  ├─ 레코드 경계 오류 [SPLIT]
│  │  ├─ 1 여러 원문 항목을 한 레코드로 합침
│  │  ├─ 2 한 원문 항목을 여러 레코드로 분리
│  │  └─ 3 개체 동일성 판단 오류(다른 개체 합침·같은 개체 분리)
│  ├─ 그룹·중첩 오류 [GROUP]
│  │  └─ 1 레코드를 잘못된 그룹·중첩 위치·레코드 종류(항목·소계·합계)에 둠
│  ├─ 배열 대응 오류 [ARRAY]
│  │  └─ 1 병렬 배열 길이·행 대응 불일치
│  ├─ 값 구성 오류 [COMPOSE]
│  │  ├─ 1 한 원문 값·서술을 여러 필드·값으로 나눌 때 경계 오류
│  │  └─ 2 여러 원문 조각을 한 값으로 합칠 때 누락·혼입
│  └─ 순서 오류 [ORDER]
│     └─ 1 원문 순서를 지켜야 하는 레코드·복수 값의 순서 위반
│
└─ 계약 오류 [CON]
   ├─ 스키마 위반 [SCHEMA]
   │  ├─ 1 필수 키 누락·허용되지 않은 키 추가
   │  ├─ 2 타입 불일치
   │  └─ 3 단일·복수 값 개수 규칙 위반
   ├─ 값 제약 위반 [RANGE]
   │  ├─ 1 허용 목록 밖의 값
   │  ├─ 2 형식이 틀린 날짜·코드·숫자
   │  ├─ 3 계약에 정의된 필드 간 제약 위반(날짜 순서·합계식 등)
   │  └─ 4 계약에 정의된 문서 간·묶음 단위 제약 위반
   ├─ 근거 오류 [EVID]
   │  ├─ 1 계약상 필수 위치·출처 근거 누락
   │  ├─ 2 근거 ID·좌표의 참조 무결성 위반
   │  └─ 3 근거가 다른 위치를 가리키거나 값과 불일치
   ├─ 직렬화·완료 오류 [DONE]
   │  ├─ 1 직렬화 문법 오류
   │  ├─ 2 중복 키로 인한 값 소실·덮어쓰기
   │  ├─ 3 응답 잘림·불완전한 출력
   │  └─ 4 일부 페이지·레코드만 처리하고 전체 완료로 표시
   └─ 공개 규칙 위반 [PRIV]
      ├─ 1 출력 금지·가림 대상 값 노출
      └─ 2 가림 형식 위반
```

## 분류 경계와 집계 기준

### 결과 유형 사이

- **미추출과 계약 오류:** 필수 키 자체가 없으면 계약 오류, 키는 있지만 원문 값을 못 채웠으면 미추출이다. 선택 키 생략이나 스키마가 허용한 null은 그 자체로 오류가 아니다.
- **키 표기 차이:** 계약에 정식 키가 정해져 있으면 `E.CON.SCHEMA.1`이다. 정식 키가 정해지지 않아 출력과 정답지가 서로 다른 표기를 쓰면 `AUX.EVAL`로 두고 평가 계약 미확정으로 표시한다.
- **미추출과 구조 오류:** 내용은 남아 있고 단위만 합쳐지거나 나뉘었으면 구조 오류, 내용 자체가 사라졌으면 미추출이다. 둘이 함께 생기면 같은 원인 사건으로 연결한다.
- **오추출과 과추출:** 원문에 있는 값을 잘못 읽거나 배정하면 오추출, 원문에 없는 내용이나 중복 레코드를 더하면 과추출이다. 원문에 있지만 범위 밖인 머리말 등을 본문으로 인식하면 Parse는 요소 유형 오인식, Extract는 범위 밖 내용 포함이다.
- **빈칸을 채운 경우:** 정답이 빈칸인 자리에 무엇을 채웠는지로 나눈다.
  - 결측 표기값(`0`·대시·`해당 없음`)으로 바꾸거나 그 반대면 `E.WRG.NORM.3`
  - 원문 다른 칸의 값을 그 칸에도 남긴 채 복사했으면 `E.OVR.DUP.2`
  - 원문 다른 칸의 값을 옮겨 와서 원래 칸이 비었으면 `E.WRG.ASSIGN.*`
  - 원문 어디에도 없는 값이면 `E.OVR.GEN.1`
  - 다른 값에서 계산·추론한 값이면 `E.OVR.GEN.2`
- **한 글자·기호가 빠진 경우:** Parse 결과에 이미 없으면 `P.MIS.CHAR`, Parse에는 있는데 Extract 출력에서 빠지면 `E.MIS.PART.1`, 다른 글자로 바뀌었으면 `READ.1`, 정규화 규칙이 지웠으면 `E.WRG.NORM.4` 또는 `AUX.POST.NORM`이다.

### 내용·속성

- **판독과 정규화:** 정의된 변환 규칙의 결과가 틀렸으면 정규화 오류, 규칙과 무관하게 옮기는 중에 값이 바뀌었으면 판독 오류다. 계약이 허용한 계산(나이·일수 등)의 결과가 틀린 것도 정규화(`NORM.2`)다. 과정규화 여부는 평가 계약의 원문 보존 정책을 따른다.
- **원문 문자 표현 보존:** 원문(인쇄·텍스트 층)에 이미 있는 전각·자모 분리·보이지 않는 문자·하이픈 변종을 그대로 옮긴 것은 Parse 오류가 아니다. Parse가 다른 코드로 바꿨을 때만 `P.WRG.READ.5`다. 그 뒤 숫자 해석 실패는 `E.WRG.NORM.2`, 사전·마스터 대조 실패는 `AUX.REF`다.
- **괄호·기호와 글자 서식:** 괄호·`△`·`▲`는 문자다. 빠지면 `P.MIS.CHAR.2`, 남았는데 부호로 해석하지 못하면 `E.WRG.NORM.2`다. `P.MIS.MARK.4`는 색·굵기·음영·밑줄처럼 문자 코드에 없는 서식만 다룬다.
- **선택 표시:** 표시의 유무·위치를 잘못 보면 `P.WRG.STATE.1`·`E.WRG.READ.3`, 표시를 맞게 봤으나 표기 관례(`X`=해당 없음 등)를 잘못 해석하면 `E.WRG.NORM.1`, 표시 기호를 글자로 읽어 값에 섞으면 Parse는 `P.OVR.FALSE.1`, 이미지에서 직접 읽은 Extract는 `E.WRG.READ.3`이다. 위치·경계 노드(`POS`·`SPLIT`)는 표시에도 적용한다.
- **배정과 사실 속성 해석:** 값을 다른 필드에 넣으면 배정 오류, 같은 필드에 넣었지만 확실성·시점·주체를 잘못 해석하면 사실 속성 해석 오류다. 질문·인용·전언 같은 진술 출처 차이는 확실성(`ATTR.1`)으로 본다.
- **같은 역할의 값이 여럿일 때:** 역할 라벨로 구분된 값(진료일·발행일)을 다른 역할 필드에 넣으면 `E.WRG.ASSIGN.3`이다. 같은 라벨·역할의 후보가 여럿이거나 공용 라벨이 여러 필드의 후보일 때 선택 규칙을 잘못 적용하면 `E.WRG.PICK.1`이다. 라벨·역할은 맞지만 다른 개체(다른 사람·방문)에 속한 값이면 `E.WRG.CTX.4`, 서술문 안 주체 해석이 틀리면 `E.WRG.ATTR.3`이다.
- **후보 선택과 배정:** 선택한 값을 다른 역할의 필드에 넣으면 배정 오류다. 여러 값을 모두 보존해야 하는 계약에서 일부만 출력하면 `E.MIS.PART.3`이다.
- **계산·추론 값:** 원문에 없는 값을 계산·추론해 원문값처럼 내면 과추출(`GEN.2`)이다. 계약이 계산값을 허용한 필드는 원문값과 구분해 기록한다. 검증식이 통과했다고 원문값이라는 증거가 되지 않는다(계산값은 식과 항상 맞는다). 값은 같고 출처 표시(원문·계산·참조)만 틀린 것도 K8 속성 차이로 `GEN.2`에 기록한다.
- **보류의 두 방향:** 원본이 실제로 읽기 어렵거나 근거가 상충하면 보류가 정상이다. 사람이 확실히 읽을 수 있는 값을 보류했으면 과보류(`ABST`)다. 반대로 보류가 필요한 원문을 추측해 확정값으로 내면 `HOLD.1`, 원문에 값이 아예 없는데 채우면 `GEN.1`이다. 파이프라인이 일부를 처리하지 못했는데 완료로 표시하면 `E.CON.DONE.4`, 원문 자체가 불완전한데 완전으로 표시하면 `HOLD.2`다.

### 구조

- **레코드 종류:** 레코드 종류(항목·소계·합계·쪽 합계·머리글) 판정이 틀리면 `E.STR.GROUP.1`이다. 계약이 그 종류를 제외하는데 출력하면 `E.OVR.SCOPE.1`, 포함하는데 빠지면 `E.MIS.TARGET.2`다.
- **머리글 손실:** 머리글만 사라졌으면 `P.MIS.UNIT.2`, 표 전체가 본문으로 인식됐으면 `P.WRG.TYPE.2`다. 머리글 의미를 잘못 연결해 열 전체가 맞바뀌면 원인은 `P.STR.REL.2` 또는 `E.WRG.CTX.1`, 결과는 `E.WRG.ASSIGN.2`에 오류 패턴 일괄로 기록한다.
- **문서 경계와 개체 귀속:** Parse가 문서 분할을 잘못 복원한 경우와, 경계는 맞는데 Extract가 다른 개체·사건의 값을 연결한 경우를 구별한다.
- **수정 표시와 문서 버전:** 표시 상태를 잘못 읽으면 판독·상태 인식, 표시와 값의 연결을 잃으면 관계 복원, 바르게 읽고도 폐기된 값을 채택하면 해석 또는 후보 선택 오류다. 버전 우선순위는 업무 계약을 따르며 발행일만으로 단정하지 않는다.
- **쪽 순서:** 입력 쪽 순서가 뒤바뀐 것을 복원하지 못하면 `P.WRG.ORDER.1`, 파이프라인이 순서를 바꾸면 `AUX.RUN`이다.

### 계약·탐지

- **값 제약 위반과 내용 오류:** 제약 위반은 탐지된 사실이다. 실제로 틀린 값이 확인되면 그 값의 오추출·과추출 유형을 함께 기록한다. 검증식 불일치 자체는 `탐지 경로`이며 계약에 정의된 제약일 때만 `E.CON.RANGE.3`·`.4`로 센다. 원문 자체가 제약을 어기게 인쇄됐으면 출력 오류가 아니다. 처리 상태를 `원문 불일치`로 기록하고, 이를 고쳐 원문과 다르게 내면 `AUX.POST.ALTER`다.
- **근거와 완결성:** 근거 오류는 값 정답률에 넣지 않고 근거 정답률로 따로 집계한다. 유효한 직렬화도 내용이 완전하다는 증거는 아니다. 부분 처리의 값 누락과 잘못된 완료 상태는 같은 원인 사건으로 연결한다.
- **공개 규칙:** `E.CON.PRIV`는 출력 안의 노출만 다룬다. 로그·중간 산출물 누출은 출력 차이가 아니므로 보안 사안으로 따로 다룬다. 원문에서 가려진 부분을 복원하면 `GEN.1`이다.

### 원인·집계

- **원인과 영향:** 병합 셀 복원 실패 같은 원인 사건과 그 결과로 생긴 여러 셀의 오배정을 연결한다. 원인 사건 수와 영향받은 단위 수를 따로 센다. 행·열 통째 밀림이나 행·열 전치는 새 유형이 아니라 `오류 패턴` 축으로 표시한다.
- **원문 범위와 정책:** 요약 단위·주석을 포함할지는 평가 계약을 먼저 정한다. 스키마가 의도적으로 제외한 내용을 누락 오류로 세지 않는다.
- **단계 귀속:** 원본 → Parse → Extract → 후처리 → 최종값을 비교해 최초로 잘못된 단계를 찾는다. 중간 결과가 없거나 복합 원인이면 귀속 미확정과 후보 원인을 유지하고, 최종 출력만으로 원인을 확정하지 않는다.
- **참조 데이터와 후처리:** 마스터·사전·코드표의 내용·버전·조회 로직이 틀렸으면 `AUX.REF`다. 참조는 맞는데 여러 후보 중 고르는 정책이 틀렸으면 `AUX.POST.PICK`이다.
- **여러 현상이 묶인 기록:** 한 기록에 여러 칸의 현상이 묶여 있으면 칸 단위로 나눠 분류한다. 나누지 않은 기록은 집계에서 따로 표시한다.

## 오류 유형과 분리할 기록 축

Depth를 늘리는 분류가 아니라 이슈마다 함께 기록할 메타데이터다. 발생 조건을 확인했다고 그것을 근본 원인으로 확정하지 않는다. 축의 구체 값은 적용 프로파일에서 시스템에 맞게 정할 수 있다.

| 기록 축 | 기록할 내용 |
|---|---|
| 오류 패턴 | 단건 / 일괄 밀림(행·열, k칸) / 전치(행↔열) / 연쇄(앞 단위 누락으로 뒤 단위가 줄줄이 어긋남) |
| 탐지 결과 | 아래 "탐지·판정 결과" 참고 |
| 업무 심각도 | 상: 업무 결정에 영향 / 중: 식별·분류에 영향 / 하: 표기·형식만 |
| 탐지 경로 | 자동 검증 실패 / 정답지 비교 / 사람 검수 / 사용자 보고 |
| 재현성 | 항상 / 간헐(같은 입력 재실행 시 달라짐) / 미확인 |
| 수정 위치 | 모델·프롬프트 / 전처리 / 후처리 규칙 / 데이터·정답지·채점기 / 정책 결정 필요 |
| 발생 조건 | 회전·저해상도·작은 글씨·가림·입력 분할 경계·긴 입력·반복 머리글·손글씨·문서 내 지시 혼입 등. 복수 태그 허용 |
| 발생 단위 | 문서·페이지·표·블록·행·셀·필드와 해당 경로 |
| 근거 수준 | 재현 확인 / 기존 기록상 관측 / 예상 시나리오 |
| 귀속 확실성 | 최초 발생 단계 확정 / 후보 단계 복수 / 귀속 미확정 |
| 처리 상태 | 정상·판독 불가·근거 부족·상충·원문 불일치·검토 필요·부분 실패 등 |
| 평가 계약 | 추출 범위·필수 근거·복수 값·버전 우선순위·계산값 허용·원문 보존 정책과 버전 |

### 탐지·판정 결과

보정 성능은 오류를 고치는 능력과 맞는 값을 건드리지 않는 능력을 함께 봐야 한다. 그래서 탐지 장치의 판단을 실제 정오와 맞대어 네 가지로 기록한다. 관측 사례 중 약 60건은 출력 차이가 아니라 이 축의 오류(검증식 오탐, 판정 상태 오표시, 근거 과다 부착)였다.

| 값 | 실제 | 장치 판단 | 결과 |
|---|---|---|---|
| 정탐 | 오류 | 의심 표시·보정 | 의도한 동작 |
| 미탐 | 오류 | 통과·확정 | 오류가 최종 출력에 남음. 높은 신뢰도로 확정된 경우를 따로 표시 |
| 오탐 | 정상 | 의심 표시·보정 | 과보류(`E.MIS.ABST.2`)나 후처리 변경(`AUX.POST.ALTER`)으로 이어짐 |
| 정상 통과 | 정상 | 통과 | — |

판정 상태를 잘못 합산하거나(규칙 결과는 맞는데 문서 상태가 틀림) 근거를 과하게 붙인 것은 출력 값의 차이가 아니므로 이 축에 `판정 집계 오류`로 남긴다. 노드별 정탐률과 오탐률은 [보정 장치 대응표](2026-10-04-issue-taxonomy-correction-coverage.md)의 측정 단위다.

## 전체 파이프라인 보조 분류

Parse·Extract 트리 밖에서 최초 원인을 기록하기 위한 보조 분류다. 결과로 나타난 Parse·Extract 유형과 반드시 연결하며 독립 원인으로 중복 집계하지 않는다.

| ID | 영역 | 보조 유형 |
|---|---|---|
| `AUX.INPUT` | 입력·디코딩·전처리 | 페이지·프레임 선택 누락, 방향 처리 실패, 이진화·리사이즈로 문자 소실, 좌표 역변환 오류, 열기·디코딩 실패를 빈 결과·성공으로 처리, 텍스트 층과 이미지 내용 불일치, 텍스트 층·이미지 혼합 페이지 일부 미처리, 입력 분할(청크·타일) 경계 처리 오류 |
| `AUX.SCHEMA` | 문서 분류·스키마 선택 | 문서 유형 오분류, 다른 스키마·추출 범위 적용 |
| `AUX.REF` | 외부 참조 | 마스터·사전·코드표의 버전 불일치, 조회 실패, 잘못된 항목 매칭, 동의어 누락 |
| `AUX.RUN` | 실행·결과 통합 | 재시도 결과 중복, 페이지 순서 오류, 다른 요청 결과 혼입, 캐시 버전 불일치, 호출 실패·시간 초과로 단위 미처리, 결정된 교정이 최종 출력에 반영되지 않음 |
| `AUX.POST.PICK` | 후처리 | 복수 후보 중 오선택 |
| `AUX.POST.EVID` | 후처리 | 근거가 잘못된 값 채택 |
| `AUX.POST.VALID` | 후처리 | 검증 결과 과신: 통과를 정답 근거로 오인해 틀린 값 확정, 또는 검증 오탐으로 맞는 결과를 폐기·대체 |
| `AUX.POST.ALTER` | 후처리 | 교정이 원문에 없는 내용을 추가하거나 위치를 바꾸거나 맞는 값을 지움 |
| `AUX.POST.NORM` | 후처리 | 정규화·변환 오류(과정규화, 반올림·절사 순서 오류 포함) |
| `AUX.EVAL` | 평가·정답지 | 정렬 오류, 정답지 오기·누락, 채점 범위·표기 정책 불일치, 정식 키 미확정 |

후처리가 정답을 바꾸지 않고 앞 단계 오류를 그대로 통과시킨 경우는 후처리 오류가 아니라 `탐지 결과` 축의 미탐으로 기록한다. 입력 문구를 모델 지시로 따른 경우는 `문서 내 지시 혼입` 발생 조건을 남기고 실제 생성·변경·누락·계약 위반을 결과 유형으로 연결한다.

## 원인 전파 기록 예시

| 구분 | 기록 |
|---|---|
| 최초 원인 | `P.STR.REL.1` 병합 셀 범위 복원 실패 |
| 후속 증상 | `E.WRG.ASSIGN.2` 값을 옆 열에 배정 |
| 오류 패턴·영향 범위 | 일괄 밀림(열, 1칸), 영향받은 행·셀 수 |
| 탐지 결과 | 미탐(합계식이 우연히 맞아 통과) |
