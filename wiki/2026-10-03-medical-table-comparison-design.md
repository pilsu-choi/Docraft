## 현행 기준

Docraft dev의 AWS 배포 예제 `deploy/aws/.env.aws.example`과 `backend/config.py`, `backend/engine.py`에서 확인한 구성이다. 실제 가동 서버의 환경변수·모델 revision·배포 커밋은 이번 작업에서 확인하지 않았다. 로컬 `.env.example`의 `PARSE_PROVIDER=library`는 일반 파싱용 개발 기본값이므로 비교군으로 쓰지 않는다. 하네스가 호출하는 `/api/read`는 `backend/verify.py`에서 paddle 경로를 명시해 읽으며 원격 OCR endpoint가 필요하다.

| 단계 | 기준 구성 |
|---|---|
| 문서 파싱 | `PARSE_PROVIDER=paddle`, `PADDLEOCR_MODEL=PaddleOCR-VL-1.6-0.9B` |
| 보험 필드·표 추출 | `qwen/qwen3-vl-32b-instruct`, 파싱 결과와 원본 페이지 이미지를 사용 |
| 출력 | `TABLE_EXTRACT=rowmajor`: 인쇄 열 순서와 행별 값 배열을 받고 보험 스키마 JSON으로 변환 |
| 선택적 처리 | 회전·열 배치·여러 쪽 처리, 실패 또는 표 게이트에 따른 asis 재추출, 예산 내 재처리 |
| 표 전체 사전 교정 | 배포 예제에서는 `TABLE_REFINE=false`. 실제 기준 환경이 true이면 별도 실행군으로 명시 |
| 추론 설정 | `AI_VISION=true`, `AI_REASONING=off`, 표 재검사 비율 설정 `0.6` |

전체 운영 흐름은 Agentic OCR 1차 결과 → harness 규칙·마스터·검증 → 필요 시 Docraft `/api/read` 재판독 → harness 최종 판정이다. Agentic OCR 내부 모델은 이 자료로 확인할 수 없다. 아래 주 실험은 Docraft 판독 경로를 비교하며, 하네스 포함 운영 성능은 별도 평가한다.

## 네 비교군

| 군 | parse | extract | 확인할 질문 |
|---|---|---|---|
| A 현행 | PaddleOCR-VL-1.6-0.9B | Qwen3-VL-32B-Instruct | 현재 dev 기준 정확도와 지연은 얼마인가 |
| B 전용 파서 교체 | PP-StructureV3와 한국어 OCR | A와 같은 Qwen3-VL-32B-Instruct | 추출 모델을 유지할 때 파서 교체만으로 이득이 있는가 |
| C 소형 추출 VLM | A와 같은 PaddleOCR-VL-1.6-0.9B | Qwen3-VL-4B-Instruct | 파서를 유지할 때 32B를 4B로 줄여도 핵심 필드 품질이 유지되는가 |
| D 전용 파서와 선택적 VLM | PP-StructureV3와 한국어 OCR | 근거가 명확한 열은 코드 매핑, 나머지 영역만 Qwen3-VL-4B-Instruct | VLM이 읽는 범위를 줄여 정확도와 지연을 함께 개선할 수 있는가 |

B에서 32B를 유지하는 이유는 파서 교체 효과만 분리하기 위해서다. 전용 파서의 HTML·셀 구조만으로 보험 스키마 추출이 완료되는 것은 아니다. B를 VLM 없는 방식이라고 부르지 않는다.

**D의 효과를 분리하려면 보조군 B4가 필요하다.** B4는 PP-StructureV3 → Qwen3-VL-4B 전량 추출이다. B4와 D의 비교에서만 선택적 호출의 개선·악화와 게이트 탐지 성능을 판정한다. 전용 파서+규칙만의 D0는 게이트·매핑 개발에 사용하는 오프라인 보조 결과로 남긴다.

## 전용 파서의 구체 구성

첫 구현 후보는 **PP-StructureV3**다. 기존 Paddle 운영 경험을 재사용할 수 있다는 판단이며, 의료비 문서에서 더 정확하다고 검증된 결론은 아니다.

- 레이아웃: `PP-DocLayout_plus-L`을 시작 후보로 고정한다.
- 문자 검출: `PP-OCRv5_server_det`을 시작 후보로 고정한다.
- 한국어 문자 인식: `korean_PP-OCRv5_mobile_rec`을 명시한다. PP-StructureV3의 중국어·영어 기본 OCR를 그대로 쓰지 않는다. 설치 버전에서 일반 OCR와 표 내부 OCR가 실제 같은 한국어 인식기를 사용하는지 출력 설정으로 확인한다.
- 표 구조: 선 있는 표와 없는 표용 `SLANeXt_wired`, `SLANeXt_wireless`를 시작 후보로 사용하고 실제 선택 모델을 기록한다. 셀 검출·문자 배정 관련 하위 모델도 파이프라인 YAML과 가중치 revision으로 고정한다.
- 출력: 표 영역, 행·열, 병합 셀, 문자, 가능한 좌표·점수, HTML/JSON을 공통 중간 형식으로 변환한다. 추측한 셀 좌표를 원문 근거로 표시하지 않는다.
- 회전 보정 정책은 비교군 공통으로 둔다. 의료비 표에 필요하지 않은 수식·차트·도장 인식은 대상 평가 범위에서 끈다. 문서 펴기는 촬영 왜곡군의 별도 비교로 다룬다.

이는 후보 명세이며 설치·연동을 검증한 구성은 아니다. 구현 단계에서 API 지원과 하위 모델 호환성을 확인한다. 근거: [PP-StructureV3 공식 사용 문서](https://www.paddleocr.ai/main/en/version3.x/pipeline_usage/PP-StructureV3.html), [한국어 PP-OCRv5 공식 모델](https://huggingface.co/PaddlePaddle/korean_PP-OCRv5_mobile_rec).

Docling TableFormer는 PP-StructureV3가 구조 인식에서 부진할 때 추가할 두 번째 파서다. 첫 실험에서 후보를 모두 늘리지 않는다. POTATR는 연구 방향 참고용으로 남기고 코드·가중치의 실제 공개 여부와 사용 가능성을 확인한 뒤 실행 후보로 올린다.

## 소형 VLM의 구체 구성

**추출 후보는 `Qwen/Qwen3-VL-4B-Instruct`**다. 현행 32B와 같은 모델 계열로 먼저 크기 축소를 검증한다. 4B가 금액·코드에서 열화하면 **`Qwen/Qwen3-VL-8B-Instruct`**를 두 번째 후보로 평가한다. 초기부터 모든 모델을 전량 실행하지 않는다.

C는 A와 동일한 이미지·OCR·보험 스키마·rowmajor 출력 계약·정규화 규칙을 사용한다. 모델 ID와 필요한 서빙 어댑터만 바꾼다. 초기 실험은 Instruct 가중치, 양자화하지 않은 동일 계열 정밀도, 같은 해상도·출력 상한을 사용하고 양자화는 후속 실험으로 분리한다. 실제 지원 범위 안에서 구조화 출력을 강제하고 실패·잘림은 실패 지표에 포함한다.

`PaddleOCR-VL-1.6-0.9B`는 이미 A의 파서다. 이것을 새로운 소형 추출기 후보처럼 중복 기재하지 않는다. 이 모델의 표 판독 출력을 보험 스키마로 옮기는 규칙 기반 경로는 별도 가설이다. 이미지 → Qwen 4B → 보험 JSON 직접 추출은 OCR 입력 효과를 확인하는 후속 보조군이며 C와 구분한다.

공식 모델: [Qwen3-VL-4B-Instruct](https://huggingface.co/Qwen/Qwen3-VL-4B-Instruct), [8B-Instruct](https://huggingface.co/Qwen/Qwen3-VL-8B-Instruct), [PaddleOCR-VL-1.6](https://huggingface.co/PaddlePaddle/PaddleOCR-VL-1.6). 한국어 의료비 성능과 필요한 VRAM·지연은 자체 입력과 실제 서빙 환경에서 측정한다.

## 선택적 재판독의 구체 경로

제안 흐름은 PP-StructureV3 → 셀 구조와 인쇄 머리글로 보험 열 매핑 → 완결성·값 종류·산식 검사 → 의심 영역의 원본 크롭을 Qwen 4B로 읽기 → 근거와 규칙으로 채택 또는 검토 표시다.

일반화 범위는 인쇄 머리글 별칭·셀 위치·병합 범위·페이지 경계에 근거가 있는 구조적 매핑이다. 특정 병원이나 파일명으로 분기하지 않는다. 병원별 신규 템플릿을 수작업으로 모두 만드는 방안도 기본 경로로 두지 않는다. 머리글이 없거나 열 의미가 모호하면 VLM 호출 대상이다.

| 의심 유형 | 판독 범위 | 판독 입력 |
|---|---|---|
| 단가·금액·코드 문자 오독 | 해당 행, 필요 시 인접 행 | 원본 해상도 크롭과 열 머리글 |
| 열 의미 또는 열 밀림 | 표 머리글과 관련 행, 필요하면 표 전체 | 전체 열 관계가 보이는 크롭 |
| 원문 행과 출력 행의 불일치 | 누락 의심 영역 | 독립 OCR 줄·셀 증거와 주변 행 |
| 다음 쪽 첫 행의 분류·연결 모호 | 앞쪽 마지막 영역과 다음 쪽 머리 영역 | 두 영역의 원본 및 페이지 번호 |

원문 자체에 표가 검출되지 않는 경우에는 파서 출력만 보고 정상이라고 판단할 수 없다. 숫자 줄 군집 등 별도 누락 신호를 사용하고, 초기 검증에서는 게이트가 통과시킨 문서도 전량 정답과 대조한다. 신뢰도 점수 하나와 산식 통과만으로 자동 통과시키지 않는다. 산식은 인쇄 필드와 실제 산정 의미가 확인된 행에서만 사용한다.

VLM에 정답 후보를 주고 확인만 요구하는 방식 대신 원본과 읽을 항목을 제공한다. 결과는 페이지·영역·행 식별자와 함께 돌려받고 인접 정상 행을 덮어쓰지 않는다. 초기 호출 예산은 문서당 최대 2회로 제안하되, 긴 문서에서 충분한지는 검증한다. 남은 오류는 검토 대상으로 남기고 정확도·자동 처리율·예산 초과를 함께 보고한다. 32B로 최종 폴백하는 변형은 호출을 숨기지 않고 별도 D32 군으로 분리한다.

이 매핑·게이트는 신규 구현이 필요하다. 현재 하네스의 규칙 기반 추출만으로 완성돼 있다고 전제하지 않는다. 특히 세부내역서보다 열 의미가 명확한 영수증부터 D를 시험하고 세부내역서로 확장하는 순서를 권고한다.

## 실행 순서와 평가 계약

1. **동결**: 실제 기준 커밋·서버 설정·모델 revision을 기록한다. 기존 59건은 이미 여러 개선에 사용됐으므로 회귀·개발 자료로 사용하고 새로운 일반화 점수로 부르지 않는다.
2. **선별 평가**: 검수한 영수증·세부내역서 각 10건, 총 20건으로 A·B·C를 비교한다. 단일·여러 쪽, 조밀한 숫자, 병합·생략, 회전·촬영 왜곡, 원내/EDI 코드 동시 존재를 포함한다. 구조·문자·의미 배정의 오류를 구분한다.
3. **매핑 평가**: 저장한 파서 출력으로 D0의 열 매핑과 게이트를 개발한다. 문서 전체를 통과시켰는데 누락을 놓친 사례를 반드시 포함한다.
4. **호출 절감 평가**: B4와 D를 같은 새 검수 문서에서 비교한다. 4B가 부진한 오류 유형만 8B 또는 D32에 추가한다.
5. **홀드아웃**: 200건 초안 테스트셋 중 인간 검수가 완료된 새 문서를 병원·양식 기준으로 분리한다. 예시 초기 목표는 60건이나 유효한 검수 표본 수와 신뢰구간에 따라 늘린다. 모든 후보를 200건씩 무조건 호출하지 않는다.

parse 점수는 표·행 탐지와 구조·글자 정확도, extract 점수는 최종 보험 필드·금액·코드 exact match와 행 recall·precision, 문서 완전 정답률로 나눈다. 빈칸 포함 셀 정확도와 비어 있지 않은 셀 정확도를 함께 보고한다. 사람 검토가 필요한 결과를 정답으로 간주하지 않고 자동 적재 비율과 그 집합의 오류율을 분리한다.

최초 추출과 선택적 재처리 후 점수를 모두 저장한다. 하네스 평가에서는 같은 AO JSON·규칙셋·마스터·폴백 예산을 사용하며 Docraft 호출 대상이 고정된 오프라인 비교와 라우팅이 변할 수 있는 전체 업무 비교를 구분한다.

지연은 `전처리 + parse + 매핑/extract + 검증 + 선택적 재판독 + 직렬화/전송`의 전체 시간과 단계별 시간을 기록한다. 단건 warm 실행과 동시 처리 실행을 분리하고 cold 시작·캐시 적중·오류·타임아웃도 남긴다. A의 32B가 외부 API이고 C의 4B가 자체 호스팅이면 모델 크기 효과와 네트워크·큐 효과가 섞인다. 현 배치 기준의 실용적 비교와 동일 서버/추론 엔진 기준의 모델 비교를 나눠 보고한다. B·D에서 쓰는 Korean mobile OCR와 A의 VLM OCR의 차이도 파서 구성 전체의 효과로 해석한다.

성공 여부는 평균 셀 점수 하나로 정하지 않는다. 금액·코드 오류와 행 누락이 악화하지 않는지 먼저 확인하고, 허용 가능한 품질 범위 안에서 p50·p95와 비용이 줄어드는 구성을 선택한다. p95의 표본 불확실성과 문서 단위 bootstrap 신뢰구간을 함께 제시한다.
