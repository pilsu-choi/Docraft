# 자연 문서 자동 교정과 서식 인쇄 정렬 추론

날짜: 2026-09-28  
브랜치: `fix/natural-corrections`  
워크트리: `Docraft/.worktrees/natural-corrections`

## 문제와 처리

일부 영수증은 가변 인쇄값 전체가 미리 인쇄된 라벨·격자보다 약 한 행 위에 놓인다. 같은 OCR 줄 또는 가장 가까운 줄의 숫자를 라벨에 붙이면 금액 열이 한 행씩 밀려도 `exact` 근거처럼 보인다. 반대로 개별 금액의 출처가 미확정이라 재처리 결과를 모두 버리면 등록된 합계식으로 확정할 수 있는 교정도 놓친다.

재처리는 의료 합계식 대상에서 충분한 OCR 줄이 세로로 놓인 경우에만 원본 이미지를 ±90도 회전해 각 OCR 시도를 예산에 센다. 회전 OCR 좌표는 원본 페이지 좌표로 되돌린다. 같은 OCR 블록의 **서로 다른 날짜 라벨 두 곳**에서 유효한 날짜 값이 동일한 방향·거리로 밀려 있는지 확인하고, 해당 공통 오프셋을 금액 라벨에 적용한다. 금액마다 대응 OCR 숫자가 하나이고 구성항 모두에 라벨·숫자·좌표 근거가 있을 때만 `FIELD_SUMS`의 등록 관계로 총액을 계산한다. 구성항과 총액은 한 후보로 검사해 함께 채택하며, 다른 필드의 기존 근거와 규칙 판정은 보존한다. 직접 인쇄된 총액이 계산값과 다르면 추론을 거절한다. 관계·문서 유형·대상 필드·각 구성항 값과 근거는 `derived_sum` 증거에 기록한다.

검증된 이미지 셀의 빈칸은 숫자 0과 다르게 `null` 후보가 된다. 본문에 같은 필드의 값이 인쇄된 경우에는 빈 셀 하나만으로 값을 지우지 않는다. 스키마에 명시된 날짜 별칭과 체크 표시의 선택 관계도 역할 근거가 있을 때만 교정 후보로 사용한다. 모든 스칼라 텍스트의 전체 이미지 재판독에는 앞선 OCR 문장을 전달하지 않는다. 길이가 긴 텍스트를 ROI에서 바꾸려면 이 독립 판독값과도 일치해야 한다. 이는 원문 OCR 오독을 모델이 그대로 반복해 짧은 이름까지 오교정한 사례를 막기 위한 것이다.

## 예산·검증·한계

기본 추가 재처리 상한은 60초, 4시도, 2모델 호출이다. 필요하면 서버 환경변수로 최대 180초·8시도·4모델 호출까지 실험할 수 있으나 최초 읽기를 포함한 요청 시한과 취소가 우선한다. 같은 값·같은 품질의 규칙 재평가는 시도를 소비하지 않고, ROI 재판독이 같은 실패 근거를 반복하면 다음 필드로 이동한다. 회전 OCR은 모델 호출이 아니라 시도를 각각 소비한다.

자연 표본 한 건의 실제 `/api/read` 재실행에서 합계와 구성항 **3개 필드가 3회 채택**됐고, 독립 원본 판독 silver 라벨의 해당 3개 값과 모두 일치했다. HTTP 요청 시간은 67.81초, 추가 재처리는 42.66초·8시도·추가 VLM 2회였으며 최초 추출 VLM과 표 정제 호출은 별도다. 동결된 최초 필드와 OCR 캐시를 사용한 별도 재생은 같은 3개 필드를 4시도·추가 VLM 0회로 교정했지만, 그 수치를 실제 API 비용으로 취급하지 않는다. 이는 한 문서의 확인 결과이며 전체 문서 정확도나 5건 이상 문서 교정을 뜻하지 않는다. 원문 및 추론 trace에는 민감값이 있으므로 비식별 집계만 문서화한다.

OCR 문자열 일치는 픽셀 진실의 보증이 아니다. 두 날짜 anchor의 오프셋이 다르거나, 라벨 또는 숫자 대응이 복수이거나, 총액식 관계가 등록되지 않은 문서는 자동 교정하지 않는다. 회전 OCR·전체 이미지 교차판독은 예산을 소비하므로 뒤쪽 미확정 필드까지 도달하지 못할 수 있다. 원격 호출의 단계별 timeout은 전체 요청의 강제 종료 시각이 아니므로 실제 벽시계 시간이 시한을 넘을 수 있으며, 반환 뒤 시한을 다시 확인하고 늦은 후보는 채택하지 않는다. 서식 밖에서 값이 읽히거나 일반 텍스트가 여러 줄에 걸친 문서는 기존 검토 경로가 남는다.

## 자연 표본과 독립 평가

35개 원본 중 13개 문서에 대해 예측값을 보지 않는 독립 모델 검토 라벨을 보강했다. 이를 사람 확정 gold로 취급하지 않는다. 최초 추출값·원본을 변조하지 않고 동결한 재처리 기본 예산 14문서 실험에서 금액 오독 3개와 명시적 빈칸의 0 오추출 2개, 총 3문서 5필드가 독립 원문 판독과 일치하도록 교정됐다. 1,254필드의 검토 대상은 192→186이며, 근거만 보강된 1개는 값 교정에서 제외했다.

그중 같은 6문서를 첫 확대 조건으로 비교했을 때 기본 5개 정답·0개 오교정·7회 추가 VLM·305.135초, 확대 5개 정답·1개 오교정·22회·633.970초였다. 잘못된 성명 채택은 Luna와 Sol의 별도 원본 판독에서 확인됐다. 이 실패를 숨기지 않고 텍스트 전체 이미지 재판독의 OCR 입력을 제거했으며, 수정 후 확대 재실행은 5개 정답·0개 오교정·22회·684.325초였다. 같은 코드의 기본 예산 대조를 별도로 수행한다.

위 수치는 선별 표본의 재처리 결과이며 전체 데이터 정확도가 아니다. 호출 수는 실제 청구액이 아닌 비용 대용 지표이고, 더 강한 모델로 바꾸는 실험은 포함하지 않았다. 개인 원문·값·실행별 코드 해시·원본 해시·라벨은 Git 제외 평가 폴더에 보관한다. 최종 전체 pytest는 616개 통과했다.

## 목표와 판정

자연 발생한 오독의 올바른 자동 교정 채택 5건 이상을 목표로 한다. 교정 필드 수와 서로 다른 원본 문서 수를 따로 기록한다. 원본·초기 추출값을 인위적으로 변조하지 않는다. 정답 라벨을 후보 생성·채택 로직에 입력하지 않는다.

기존 silver와 초기 결과의 불일치는 후보 탐색에만 사용한다. 원본만 보는 독립 모델 판독, 별도 원문 재검토, 근거 좌표와 before/after 비교를 거쳐 올바름을 판정한다. 모델 합의는 인간 확정 gold로 표시하지 않는다. 모호한 필드는 unknown으로 남긴다. 값의 실제 변화가 없는 근거 보강과 날짜 표기만의 변화는 교정 성공 건수에서 제외한다. 금액 null과 0도 구별한다.

## 사용자 우선순위 보강

미확정 필드와 사람 검토를 최대한 줄이는 자동 판독·교정이 1차 목표다. 직접 문자 일치에 한정하지 않고 서식·선택 관계·날짜 역할·합계식·반복 표기·주변 문맥으로 유일한 답을 도출하면 추론 근거를 기록하고 자동 채택한다. 원문 확정, 문맥·계산 추론, 미확정을 구분하되 추론이라는 이유만으로 사람 검토에 보내지 않는다.

교정 5건은 최소 실증 목표로 유지하고, 미확정 감소량·자동 처리율·오교정 건수를 함께 측정한다. 독립 판독자는 예측값을 보지 않고 추론 근거와 대안을 기록한다. 평가 라벨을 런타임 후보 생성에 입력하지 않는 원칙은 유지한다.


## 정확도 우선 예산 비교

사용자가 시간·비용이 추가되더라도 정확도 개선 여부를 먼저 검증하도록 요청했다. 같은 자연 원본·초기 추출값에서 기본 60초/4단계/추가 VLM 2회와 확장 180초/8단계/추가 VLM 4회를 비교한다. 비교 전 운영 기본값은 변경하지 않는다. 확장 실험의 외부 deadline은 300초이며 재처리 내부 상한은 180초다. 올바른 교정·오교정·미확정 감소·소요 시간·추가 호출 수를 보고한다. 실제 청구액을 확인하지 못하면 호출 수를 비용 대용 지표로 표시하고 금액을 추측하지 않는다.

## 발견한 오류와 개선 방향

- 회전된 약제비영수증에서 가변 인쇄 내용이 서식 항목명보다 한 행 위로 밀렸다. 같은 행의 숫자를 연결하는 방식 자체가 틀릴 수 있다. 서로 다른 날짜 항목 두 곳의 동일한 인쇄 오프셋, 유일한 금액 연결, 등록된 합계식을 함께 검증하는 추론을 추가한다.
- 주소 재판독의 첫 수정안에서 1건의 잘못된 교정 채택이 발견됐다. 올바른 교정 건수에서 제외하고, 후보값·동일 OCR을 주지 않는 전체 이미지 재판독과의 일치를 요구하도록 보완한다.
- 날짜 칸이 비어 있어도 본문에 두 입원 기간이 나오는 표본이 있다. 칸의 공백만으로 날짜 전체를 미기재로 확정하지 않는다.
- 기존 평가 도구의 금액 null/0 느슨한 동치는 이번 독립 채점에 사용하지 않는다. 명시적 빈칸과 숫자 0, 형식만 다른 동일 값을 구분한다.

비공개 산출물은 `Docraft/data/verify/natural-corrections-20260928/`에 저장한다. `baseline-fields`에는 원본·parse·extract 해시와 초기 정규화 커밋을 기록했다. 라벨은 모델 독립 검토이며 인간 확정 gold로 표시하지 않는다.

## 수정 후 중간 실증

회전·인쇄 위치 보정의 자연 표본에서 동결 초기값 재생은 3필드 교정, 4시도, 추가 VLM 0회였다. 별도의 새 `POST /api/read` 전체 추출에서도 동일한 금액 3필드를 자동 교정했고 독립 라벨 3개와 일치했다. 이 API 실행은 HTTP 200, 전체 67.81초, 재처리 42.66초, 8시도·추가 VLM 2회였다. 초기 추출과 표 보강 호출은 재처리의 추가 VLM 횟수에 포함하지 않는다.

이전 주소 오교정은 후보값이나 동일 OCR을 주지 않는 전체 이미지 확인과 일치하지 않아 거절됐다. 빈 금액 칸의 잘못된 값은 독립 원본 판독과 닫힌 물리 셀의 영상 근거로 확인한다. 기울어진 셀은 원본 polygon과 이를 감싸는 bbox를 함께 보관하며, 축 정렬 셀인 것처럼 표시하지 않는다.

최종 대조 실험은 코드와 parse·초기 추출값을 동결하고 기본 예산 14문서, 동일 집합 중 확대 예산 6문서로 진행한다. 원본·OCR·추출값·실행 코드 해시와 예산은 비공개 `final-protocol.json` 및 각 결과 파일에 기록한다. 명목 시한은 원격 HTTP 동작 전체를 강제 종료하는 벽시계 제한과 다르며, 늦게 끝난 호출의 결과는 채택 직전 시한을 재확인해 제외한다.

## 같은 6문서에서 확인한 예산 효과

동일 코드·동일 원본·동일 초기값·동일 parse를 해시로 확인한 비교다. 기본 예산 전체 실험은 14문서, 이 표는 확대 실험을 함께 수행한 6문서만 비교한다.

| 조건 | 올바른 값 교정 | 오교정 | 추가 VLM 호출 | 재처리 시간 합계 | 검토 대상 필드 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 기본 60초·4단계·2회 | 5 | 0 | 7 | 305.135초 | 90→84 |
| 확대 180초·8단계·4회 | 5 | 1 | 22 | 633.970초 | 90→83 |

확대 조건에서 줄어든 마지막 검토 필드는 실제로 잘못된 성명 교정이었다. Luna와 Sol이 후보·기존 라벨을 보지 않고 원본 성명 행을 각각 판독했으며 두 독립 판독이 일치했다. 이 사례를 정답 교정으로 세지 않는다. 주소 라벨 역시 재검토에서 일부 불확실성이 발견되어 기존 라벨 값을 보존하고 unknown으로 제외했다.

이 비교에서는 추가 호출 약 3.14배·재처리 시간 약 2.08배에도 정답 교정이 늘지 않았다. 시도 상한이 두 배여도 실제 호출은 기본 조건의 미사용 예산 때문에 두 배보다 더 늘 수 있다. 예산 확대만으로 정확도가 좋아진다고 판단할 근거가 없으며, 추가 시도에서 OCR 오독을 다시 따라 읽은 텍스트 채택 경로를 보완한다. 수정 후 검증은 위 동결 대조 실험과 별도로 기록한다.

14문서 기본 조건에서는 1,254필드 중 재처리 직전 검토 대상 192개가 186개로 줄었고, 3문서의 5필드에서 올바른 값 교정을 확인했다. 금액 오독 3개와 명시적 빈칸의 0 오추출 2개다. 근거만 보강된 1필드는 값 교정 건수에서 제외한다. 전체 문서의 정답 정확도를 뜻하는 비율이 아니라, 선별 자연 표본의 재처리 결과다.

## 오교정 경로와 후속 통합

확대 실험에서 짧은 성명까지 오교정한 원인은 전체 이미지 재판독에 앞선 OCR 문자열을 함께 주어 같은 오독을 반복할 수 있었기 때문이다. 모든 스칼라 텍스트의 `wide_vlm`에는 기존 OCR을 전달하지 않도록 변경했다. 이는 정답 보장이 아니라 입력 편향을 줄이는 조치이며, 수정 전 확대 실험의 오교정 1건 기록은 보존한다. 수정 후 기본·확대 조건을 같은 코드로 다시 비교한다.

Harness에는 검증된 등록 합계의 구성항을 함께 요청하고 같은 응답의 근거·값·문서 전체 규칙을 재검증하여 한꺼번에 반영하는 경로를 추가했다. 개별 후보와 최종 결합 후보 모두 새로운 규칙 FAIL이 없어야 한다. 검증된 숫자 빈칸의 0→null은 최종 직렬화에서도 원래 0을 남기지 않고 null을 반영한다. 기존 AO 원본은 보존한다.

자연 표본 22·24·33에 정확히 대응하는 AO 원본 JSON은 확보하지 못했다. 실제 Docraft API/재생 근거의 Harness 소비자 검증과 합성 AO 통합 테스트를 구분한다. Docraft의 자연 교정 5건을 고객 AO 전체 파이프라인에서 실증한 5건으로 보고하지 않는다.

## 재개 및 검증 이력

세션 중단 뒤 기존 평가 프로세스가 남아 있는 상태에서 재시작 프로세스가 잠시 겹쳤다. 두 프로세스를 종료하고, 중복 전 완료된 31·33 결과만 보존한 `guarded-default-serial` 폴더에서 22·24·23·1을 단독 재실행한다. 겹친 `guarded-default` 결과는 최종 시간·호출 비교에서 제외한다. 확대 조건의 `guarded-expanded`는 중단 전 완결된 단독 실행이다.

Docraft 전체 테스트는 616개 통과했다. Harness 최종 전체 테스트는 1,554개 통과, 2개 skip, 프로젝트 설정상 8개 deselect였으며 Ruff와 diff 공백 검사도 통과했다. 재분류 테스트의 기존 fake proof는 새 계약에 필요한 `basis`·`match`를 명시하도록 수정했다. 배타 체크의 `form_choice` 전달과 재추출 proof의 대상 경로 결속도 회귀 검증했다.

## 실제 AO UI 입력 검증 확장

### AO UI 수집 완료

자연 표본 22·24·33 모두 실제 AO 외부 API 제출·결과 조회와 콘솔 extract original UI 응답 수집에 성공했다. 각 표본의 `ao-external.json`, `ao-ui-envelope.json`, `ao-ui-harness-input.json`을 `Docraft/data/verify/natural-corrections-20260928/ao-ui/{index}/`에 0600 권한으로 보존했다. 입력 문서나 AO 값을 합성·변조하지 않았으며 UI 입력 준비 시 문서 유형 코드만 기존 e2e 매핑에 따라 변환했다.

전체 연결 검증에는 Docraft `57886b0` 소스의 임시 로컬 API(`127.0.0.1:18086`)와 AWS OCR·OpenRouter, Harness `79fe3cf` 코드를 사용한다. 임시 API 재처리 설정은 확대 조건(180초·8시도·4추가 호출), 전체 read 상한 300초다. 이 실험은 동일 초기 추출값의 예산 A/B가 아니라 신규 AO 최초값을 쓰는 별도 E2E 검증이다.

### 실제 입력에서 드러난 구조 차이

33번 약제비 AO UI는 `진료비내역`을 단일 행 표로 반환한다. Docraft 스키마와 기존 Harness 등록 합계는 `진료비내역-총액` 등 스칼라 이름을 사용한다. 합성 스칼라 AO 테스트가 이 실제 구조를 포함하지 못했으므로, 등록된 단일 행 금액 그룹에 한정한 의미 매핑이 필요한지 별도 검증한다. 다중 행 표를 임의로 스칼라화하지 않는다. 로컬 E2E에서는 마스터 DB가 없어 관련 대조가 not_applicable이며, 이를 전체 고객 환경 검증으로 표시하지 않는다.

독립 라벨 대조에서 새 AO 원값도 목표 5필드 모두 오답이었다. 22 카드 필드는 0이 아닌 금액, 24 초과금 필드는 0, 33의 금액 세 칸은 다른 숫자였다. 기존 Harness의 빈칸 추가 분기는 0→null만 다뤘으므로 22는 별도의 안전성 검토가 필요하다. 닫힌 물리 빈칸의 라벨·좌표와 문서 전체 규칙을 확인하기 전에는 비0 금액을 지우지 않는다. 또한 Docraft 최초 추출이 이미 올바른 null인 경우의 PASS 근거와 Docraft 내부 재처리의 CORRECTED 상태를 구별해야 한다.

실제 AO 연결 실험은 `reread_mode=FULL`, 이미지 동봉, fallback 활성화로 전체 재판독을 요청한다. 운영 기본 선택 판독의 처리 시간·호출량 측정이 아니다. 22의 첫 Docraft 요청은 HTTP 200으로 234.45초에 끝났고, 미확정 필드에 대한 후속 요청이 이어졌다. 추가 예산 상한과 전체 재판독·fallback 요청의 비용을 동일하게 취급하지 않는다.

### AO 22 초기 연결 결과 — 이전 Harness 실행으로 최신 성과에서 제외

첫 전체 재판독 234.45초와 후속 1필드 판독 216.67초 모두 HTTP 200이었다. 최종 Harness 문서는 unresolved, 카드 칸은 기존 분기 3의 pass로 AO 비0 오답을 유지했다. 카드 재판독은 null이지만 grounding·quality가 없어 unavailable로 처리됐다. 따라서 이번 live 응답은 명시 빈칸을 증명하지 못했고, 기존 캐시 기반 Docraft 빈칸 교정 성과와 다르다. 비0→null 추가 분기를 무조건 허용하지 않았으며, 이를 실제 E2E 성공 건수로 세지 않는다. 값 정답 여부와 Harness tier를 별도로 채점해야 함을 확인했다.

### 임시 실행기의 import 경로 오류 정정

최초 AO 22·24·33 임시 스크립트는 worktree cwd에서 실행했지만 editable install 경로 때문에 기본 `harness-v2/src`를 import했다. 기본 체크아웃은 `main@09e7a76169b64d39c0c72906a6663bcb03886685`이며 새 `dev@79fe3cf` 또는 단일 행 매핑 수정 코드가 아니다. 이 실행들을 최신 Harness 성과로 보고하지 않는다. 특히 위 22의 근거 소실·판정 결과가 새 코드에도 발생한다고 단정할 수 없다. 실행기에 절대 `PYTHONPATH`와 import 경로 기록을 추가해 재검증한다. 저장된 실제 Docraft 원응답이 있으면 새 코드에서 재생하고, 없는 22는 다시 수집한다.

pytest는 `pyproject.toml`의 `pythonpath=["src"]`를 사용하므로 이 임시 실행기 문제와 다르며, 단일 행 매핑 추가 후 전체 1,558개가 통과했다(2 skip, 8 deselect).

### 현재 Harness의 AO UI 검증 결과

33은 새 단일 행 매핑을 포함한 실제 worktree 코드를 명시하고 live Docraft 응답을 받아 처리했다. 세 목표 금액 모두 AO 오답에서 독립 라벨 정답으로 바뀌었으며 최종 출력에 `repaired`·분기 `7-i`로 반영됐다. 총액은 `derived_sum`, 공단부담액·급여본인부담은 `aligned_amount`이며 세 칸의 CORRECTED 품질·원문 근거가 검증됐다. 문서 전체는 다른 미확정 필드 때문에 unresolved다. 기존 Docraft 자연 교정 5개 중 같은 금액 3개를 실제 AO 파이프라인으로 확인한 것으로, 서로 다른 8개 교정으로 합산하지 않는다.

24는 이전 live에서 수집한 실제 Docraft HTTP 200 원응답 한 건을 현재 코드로 엄격한 요청 키 일치 검사 후 재생했다. 목표 초과금은 여전히 라벨 null과 불일치하며 grounding이 없다. 현재 코드는 분기 9의 unresolved로 AO 0을 유지했다. 이는 신규 네트워크 실험이 아니라 저장 응답 재생이다. 이전 코드의 pass 판정과 다르지만 값 정답 개선은 아니다.

현재 코드의 import 경로와 runner SHA-256은 각 실행에서 검증·기록한다. 22 최신 코드 live는 별도로 재실행하여 원응답을 보존한다.
