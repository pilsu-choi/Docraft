# 룰 엔진 엣지케이스 확장

- 날짜: 2026-09-23
- 브랜치: `feat/rules-edge-cases`
- 워크트리: `.worktrees/rules-edge-cases`

## 배경

진료비영수증에서 `비급여` 값이 이웃 key `선택진료료`로 들어가는 열 밀림 제보를 계기로, 값 누락·오매핑 외의 엣지케이스를 룰로 검출·교정하도록 엔진을 넓혔다. 근거는 최신 캐시 평가(`rules` 단계 오류 873건, 76문서)와 별도로 받은 오탐 330건 필드별 집계다.

원칙은 기존과 같다. 근거가 확실할 때만 `apply`·`correct`가 고치고, 애매하면 `check`가 경고로 Judge에 넘긴다. 잘못 채우는 쪽이 비워 두는 쪽보다 나쁘다.

## 조사에서 확인한 사실

- **열 밀림 문서는 파서 머리글도 무너져 있다.** 실제로 열이 밀린 영수증 3건은 병합 셀 때문에 파서 머리글부터 `"전지 택"`, `"료 8"`처럼 뭉개져 있었다. 그래서 파서 격자로 열을 되돌리는 교정은 머리글이 온전할 때만 동작하고, 머리글이 무너진 문서는 합계와 산술로 대조하는 경로를 따로 두었다.
- **세부내역서 행별 `급여`는 AO 관례상 비어 있다.** gold(AO 예시 `2303314528`)와 silver 라벨에서 `급여구분=급여`인 행 약 300개의 `급여` 칸은 모두 null이다. `비급여` 행은 `비급여 = 총액`이다. 기존 룰이 급여 행에도 총액을 복사해 오탐 240건을 만들고 있었다.
- **영수증 항목명 오류 57건 중 이름 규칙으로 고칠 수 있는 것은 8건뿐이다.** 서식의 분류 칸 이름이 붙은 `필주사료_약품비`, `선택항목_CT진단료` 같은 경우다. 나머지는 행 누락 22건, 그로 인한 연쇄 밀림 20건, 파서 오복원 2건, 한두 글자 OCR 오독 5건이다. 오독은 별칭으로 고치면 멀쩡한 항목까지 바꿀 위험이 커서 넣지 않았다.

## 버리거나 좁힌 룰

- **소견서 진단일(제 이름 라벨 근거 없으면 비움)**: fp 5건을 없애지만 맞는 값 3건을 잃어 버렸다.
- **`row_duplicate`**: 라벨에서 뜬 1건이 실제로 인쇄된 중복 행이라 버렸다.
- **`low_quality`**: 원내코드를 쓰는 병원에서 헛경고가 나서, 행의 4분의 1 이상이 산술에도 실패해야 뜨도록 좁혔다.
- **빈 행·머리글 행 삭제**: 영수증에 적용하면 금액이 0인 인쇄 행 6개를 잃어 영수증은 제외했다.
- **세부내역서 코드 열이 하나면 원내코드 비우기**: 그런 서식에서 원내코드를 가진 라벨이 있어 넣지 않았다.

## main 병합 시 조정

main의 `64486bd`는 머리글에 독립 급여 열이 보이면 총액으로 급여를 채웠다. 이 채우기가 머리글 판별상 독립 급여 열이 있는 두 문서(`16406102833801004940650714586571`, `SA2020010683384`)에서 오탐 36건을 냈다. 라벨은 두 문서 모두 급여 값이 0건이다. 라벨 관례 ⑨("급여 값 칸이 인쇄된 서식만 채운다")는 인쇄된 값을 읽으라는 뜻이지 총액에서 계산하라는 뜻이 아니다. 그래서 총액으로 채우는 부분은 빼고, 총액을 옮겨 적은 값은 지우도록 합쳤다. 이 과정에서 `derive`에 붙었던 `blocks` 인자도 필요 없어져 원래 형태로 되돌렸다. main 테스트의 `선택항목_CT진단료 → 선택항목CT진단료` 기대값은 접두어 제거에 맞춰 `CT진단료`로 바꿨다.

## 남은 것

- 추출 프롬프트의 세부내역서 `급여` 설명 변경은 새 추출에서만 반영된다. 캐시 평가로는 보이지 않는다.
- 파서 격자 열 되돌림은 단위 테스트로만 확인했다. 머리글이 온전한 열 밀림 실사례가 생기면 다시 재야 한다.
- 영수증 항목 행 누락(22건)과 그로 인한 연쇄 밀림(20건)은 추출·파싱 단계 문제라 룰 범위 밖이다.
- 테스트는 368개 통과.
