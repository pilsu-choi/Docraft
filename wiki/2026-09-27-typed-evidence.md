# 날짜·체크·표 셀의 유형별 원문 근거

날짜: 2026-09-27
브랜치: `feat/typed-evidence`
워크트리: `Docraft/.worktrees/typed-evidence`

## 구현 계약

의료 문서 스키마의 `kind`와 기존 규칙 라벨 별칭을 사용해 날짜 `YYYYMMDD`와 원문의 `년월일`·구분자 표기를 연결한다. `진료기간` 같은 한 범위는 시작·종료 역할을 분리해 원문 날짜 token과 라벨·좌표를 각각 기록한다. 별도 사고발생일이 인쇄되지 않았는데 진료 시작일에서 파생한 값은 직접 원문 근거로 승격하지 않는다. 체크박스의 `Y/N`은 실제 체크·빈 상자 기호가 해당 라벨에 유일하게 연결될 때만 근거를 준다. 표시가 없다는 사실만으로 `N`을 증명하거나, 두 라벨 사이의 한 기호를 양쪽에 쓰지 않는다. OCR 라벨과 값이 서로 다른 줄이면 같은 가로 행의 인접 줄만 묶고, 다른 필드 라벨에서 멈춘다.

파서는 괘선으로 확인한 물리 셀에 원본 페이지 좌표와 행·열·병합 범위를 기록한다. 값 근거는 단일 검증 셀과 유일한 행·열 연결을 요구한다. 병합 상위 머리글 `본인부담액`과 하위 `급여`처럼 두 단계 라벨이 한 열을 유일하게 지정할 때만 해당 총계 셀과 스칼라 합계를 연결한다. 병합/불완전 셀을 개별 값 셀로 간주하지 않는다. 빈칸은 닫힌 단일 셀, OCR 부재, 이미지 내부 잉크 부재가 확인된 `blank=true,verified=true`에서만 `null` 근거가 된다. 인쇄된 `0`과 빈칸은 구분한다. 최초 규칙 단계 또는 ROI 재파싱에서 이 증거가 새로 생기면 해당 leaf에만 `None` 후보를 만들고, 재검증 후 채택한다. 후보 필드 누락과 `None`도 별도 sentinel로 구분한다.

typed 근거는 `match=typed|blank`, `evidence_type`, `transform`, `role`, `label`, `normalized_value`, `verified`, `geometry_scope`, 원문 `source_text`, 원본 페이지 `bbox`를 보존한다. 날짜/체크/숫자 표 값의 `basis`는 `ocr_typed`, 검증된 물리 빈칸은 `image_cell_blank`다. `field_quality.provenance`, `/api/read`의 `groundings`, 일반 문서 DB의 groundings·재처리 trace가 이 근거와 채택 상태를 유지한다. typed 원문과 최종 값의 정규형·역할·좌표가 맞지 않으면 `PASS`와 자동 채택을 허용하지 않는다. 기존 재처리 상한 60초·4시도·추가 모델 2회는 그대로다.

## 검증과 한계

합성 회귀에서 라벨 날짜/기간의 시작·종료, 분리된 OCR 줄, 체크 표시 충돌, 병합 상·하위 머리글, 표 총계 셀, `0`과 검증 빈칸, ROI에서 새로 발견한 빈칸의 `null` 채택, 미검증 셀 및 값이 다른 typed 주장 거절을 확인했다. 전체 회귀 597개가 통과했다. 기존 35건 추출 캐시에 현재 OCR 블록을 적용한 근거 판정은 PASS 2447→2448, SUSPICIOUS 667→666이었다. 줄 OCR과 물리 셀을 새로 얻은 원본 3건에서는 PASS 123→126, SUSPICIOUS 139→136, UNRESOLVED 1건 유지였다. 진단서 날짜 3개와 최종진단 체크는 근거 확인으로 SUSPICIOUS→PASS가 됐고, 영수증 두 필드는 별칭 원거리 라벨 검사로 PASS→SUSPICIOUS가 됐다. 이 수치는 **근거 상태 변화**이며 원본 정답률이나 교정 성공률을 뜻하지 않는다.

기존 OCR·격자 파서가 줄 또는 셀 좌표를 주지 않거나 병합 머리글을 오독하면 typed 근거를 만들지 않는다. 새 파서의 자연 표본 3건은 검증된 빈 셀이 0개여서 자동 `null` 교정의 실문서 성공을 입증하지 못했다. 빈칸 검증에 실패한 문서는 검토 상태로 남긴다. 사고발생일을 진료 시작일에서 파생하는 기존 스키마 관례는 별도 파생 근거 계약이 마련되기 전까지 직접 확인으로 표시하지 않는다.

## 설계 기준

- 기존 라벨·날짜·표 격자 함수를 재사용하고 동일 의미의 구현을 중복해서 만들지 않는다.
- 원문 그대로의 일치와 명시적 의미 변환을 구별하고, 실제 좌표와 원문 역할을 기록한다. 표 전체 좌표를 셀 좌표로 표시하지 않는다.
- `null`이 읽지 못함인지 확인된 빈칸인지 구분한다. 셀 위치와 비어 있다는 증거가 확인된 경우에만 잘못된 비공란 값을 비울 수 있다. 숫자 0은 빈칸으로 대체하지 않는다.
- 일반 추출·의료 API·재처리·Harness의 최종 채택까지 같은 계약을 유지한다. 기본 60초/4단계/추가 VLM 2회 예산은 유지한다.
- 불명확한 선택 상태, 날짜 역할 충돌, 불완전한 격자, 모호한 표 머리글은 검토 대상으로 남긴다.

## 근거 보존 계약

- 날짜·체크 근거는 원문 토큰, 정규화된 값, 변환 종류, 라벨 역할, 페이지·좌표를 함께 기록한다. 후보값과 원문 토큰이 같은 변환 결과를 내야 한다.
- 하나의 체크 기호를 인접한 두 라벨이 공유하거나, 날짜 탐색 중 다른 필드 라벨을 건너뛰면 자동 근거로 인정하지 않는다.
- 빈 셀은 `table_blank`/`blank_to_null`로 표시한다. 필드 누락과 명시적 `null` 후보를 구별하며, 재처리에서 새로 파싱한 셀도 후보를 만들 수 있다. 필수값·합계 규칙은 그대로 검사한다.
- ROI 셀 좌표를 원본 페이지로 되돌리고, VLM 표 교정으로 표 텍스트가 바뀌면 이전 OCR 셀 증거를 제거한다. Harness는 원본 문서 페이지 번호로 근거와 품질 정보를 함께 변환한다.

## 실제 표본의 제한

영수증(index 20)의 상한액초과금 영역은 라벨 OCR 오류, 인쇄 번호 `⑤`, 불완전한 경계, 약 1.4도 기울기가 함께 확인됐다. OCR 무텍스트만으로 공란을 확정하지 않는다. 최종 파서에서도 해당 공란은 미확정이다.

세부내역서(index 25)의 물리 셀은 존재하지만 머리글 오독·병합 구조의 의미 연결은 별도 검증이 필요하다. 전체 표 좌표나 이웃 숫자를 목표 셀의 근거로 대체하지 않는다. `사고발생일자`는 스키마의 진료 개시일 별칭이며, 원문에 실제 사고일이 인쇄됐다는 직접 근거로 표시하지 않는다.

최종 파서의 원본 3건 재생성은 이미지·페이지 크기 및 기존 OCR 텍스트·표 행·병합 구조가 같음을 확인한 뒤 수행했다. 모델 호출 없이 셀 기하만 다시 계산했다. 결과는 index 0: 29셀/검증 24/빈칸 0, index 20: 189/49/0, index 25: 47/45/1이다. 마지막 빈칸은 병합 셀이라 필드 의미까지 확증된 null 교정 사례를 뜻하지 않는다.
