# GPU 할당 방식 이원화: 카드 지정 모드 + device plugin 자원 모드

- 날짜: 2026-09-26
- 브랜치: `feat/gpu-alloc`
- 워크트리: `.worktrees/gpu-alloc`

## 배경

`deploy/k8s/helm/docraft` 차트는 `paddleocrVl`(vlm-server+api)·`paddleocrLines`·`vllmVlm` 세 GPU
컴포넌트를 `deviceIds`(카드 번호)로만 붙였다 — device plugin 을 우회해 `NVIDIA_VISIBLE_DEVICES` 를
직접 주고, `nvidia.com/gpu` 를 요청하지 않으므로 스케줄러가 GPU 노드를 모른다(그래서
`gpu.nodeSelector` 가 필수였다). 이 방식은 노드의 `nvidia-container-toolkit` 이
`accept-nvidia-visible-devices-envvar-when-unprivileged=true` 여야 동작하고(GPU Operator 기본은
false), 카드 번호를 사람이 미리 정해야 한다는 전제가 있다.

harness-installer 우산 차트의 `mlife-harness` 차트(`models.embedding`)는 이미 두 모드를 함께
지원한다 — `deviceIds` 를 비우면 `gpuCount` 장을 `nvidia.com/gpu` 로 요청해 device plugin 이 카드를
고른다. Docraft 도 같은 패턴을 쓰도록 맞췄다.

## 구현

`templates/_helpers.tpl` 의 GPU 헬퍼를 컴포넌트 값 dict(`$p`/`$l`/`$v`)를 받는 형태로 통일했다.

- `dft.gpuCount` — `deviceIds` 를 채우면 쉼표로 센 카드 개수, 비우면 `gpuCount`(기본 1).
- `dft.gpuEnv` — `NVIDIA_VISIBLE_DEVICES` 는 카드 지정 모드일 때만, `NVIDIA_DRIVER_CAPABILITIES` 는
  항상.
- `dft.gpuResources`(`dict "res" <resources 맵> "gpu" <컴포넌트>`) — device plugin 모드일 때만
  `nvidia.com/gpu: <count>` 를 requests·limits 에 병합해 얹는다(harness `models.yaml` 과 같은
  `deepCopy`/`merge` 패턴). `vlm-server`·`api`·`paddleocr-lines`·`vllm` 컨테이너와 `gpu-check` init
  컨테이너 모두 이 헬퍼를 쓴다 — kubelet 이 init 컨테이너에 배정한 GPU 를 앱 컨테이너에도 그대로
  재사용하기 때문이다.
- `dft.gpuCheck`(`dict "ctx" . "image" <ref> "gpu" <컴포넌트>`) — 두 모드 모두에서 init 컨테이너로
  남는다. 보이는 GPU 장수가 기대치와 다르면 멈추는데, 오류 메시지가 모드별로 다르다: 카드 지정
  모드는 기존 toolkit 안내, device plugin 모드는 "서로 다른 카드를 못 받았다(time-slicing 이면
  같은 카드의 복제본만 받을 수 있다)"는 안내와 `deviceIds` 대안을 제시한다.
- `dft.requireGpuNode`(컴포넌트 값 dict 를 `ctx` 와 함께 전달) — 그 컴포넌트가 카드 지정 모드일
  때만 `gpu.nodeSelector`/`nodeSelector` 부재를 막는다. device plugin 모드는 `nvidia.com/gpu` 요청만
  으로 스케줄되므로 노드 지정이 필요 없다.

`templates/vllm-vlm.yaml` 의 `--tensor-parallel-size` 는 `dft.gpuCount` 값을 그대로 쓴다.
`paddleocr-vl.yaml`·`paddleocr-lines.yaml` 의 로컬 `$count` 계산은 제거하고 헬퍼로 옮겼다.

`values.yaml` 은 세 컴포넌트에 `gpuCount: 1` 을 추가하고 `deviceIds` 기본값을 `"0"`/`"1"` 에서
`""` 로 바꿨다(기본이 device plugin 모드가 됐다). 주석에 두 모드를 함께 설명하고, 카드를 나눠 쓸
때(예: `paddleocrVl`+`paddleocrLines`)는 device plugin time-slicing 이 필요하며 GPU 메모리가
격리되지 않으므로 `gpuMemoryUtilization` 비율 합을 카드 하나에 맞춰야 한다는 점을 덧붙였다.

`deploy/k8s/README.md` 의 「값 확인 명령」·「GPU 배치」 절에 두 모드의 예시 명령과 차이를 추가했다.

## 검증

`helm`(`/home/pilsu/.local/bin/helm`, v3.21.0)으로 4가지 케이스를 `helm template`/`lint --strict`
로 확인했다.

1. **기본값(device plugin 모드), 세 컴포넌트 모두 켜짐, nodeSelector 없음** — 렌더링 성공.
   `vlm-server`·`api`·`paddleocr-lines`·`vllm`·각 `gpu-check` 총 4개 배포의 requests·limits 에
   `nvidia.com/gpu: 1` 이 16곳(4배포 × 2컨테이너 × 2(requests/limits)) 모두 들어갔고,
   `NVIDIA_VISIBLE_DEVICES` 는 없으며, `--tensor-parallel-size=1`, `nodeSelector` 블록도 없다.
2. **`vllmVlm.gpuCount=2`** — `--tensor-parallel-size=2`, `nvidia.com/gpu: 2` 로 함께 바뀐다.
3. **카드 지정 모드(`deviceIds` `"0"`/`"0"`/`"1"`) + `gpu.nodeSelector` 지정** — 변경 전(`git
   archive HEAD`로 뜬 스크래치 사본)과 `diff` 했을 때 `NVIDIA_VISIBLE_DEVICES`·`nvidia.com/gpu` 부재
   등 내용은 동일했고, 차이는 `gpu-check` 의 `resources` 가 정적 인라인 맵에서
   `dft.gpuResources` 의 `toYaml` 다중 줄 표기로 바뀐 것(같은 값, 형식만 다름)과 주석 문구뿐이었다.
   (첫 시도에서 `helm --set deviceIds=0` 처럼 따옴표 없이 주면 Sprig `default` 가 정수 `0` 을
   "빈 값"으로 취급해 오탐이 났다 — `--set-string` 으로 다시 확인해 실제 값 타입(YAML 문자열)
   기준으로는 문제없음을 확인했다.)
4. **카드 지정 모드인데 `gpu.nodeSelector` 없음** — `paddleocrVl`·`vllmVlm` 각각 렌더링이
   "deviceIds(카드 지정 모드)를 쓰면 gpu.nodeSelector 로 노드를 지정해야 한다…" 오류로 멈췄다.

`helm lint --strict` 는 기본값과 세 컴포넌트 활성화 값 모두 0 개 실패. 별도 `helm test`/bats 스크립트는
저장소에 없고, 차트 안의 `templates/tests/smoke.yaml`(helm test hook)은 클러스터가 있어야 실행되므로
이번 검증에서는 `helm template` 렌더링으로 갈음했다.

## 남은 참고

- 기본값이 device plugin 모드로 바뀌었으므로, 실제 반입 번들(카드 번호를 미리 정해 배포하는
  경로)은 계속 `deviceIds` 를 채워 카드 지정 모드를 쓴다 — README 예시 명령을 그 전제로 갱신했다.
- device plugin time-slicing 자체의 클러스터 설정(ConfigMap 등)은 이 작업 범위 밖이다 — harness-v2
  쪽에도 별도 문서가 없다면 실제 GPU 클러스터에서 설정하고 확인이 필요하다.
