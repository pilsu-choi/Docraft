# 세부내역서 급여구분 스키마 설명: 공란 칸을 급여로 채우지 않기

날짜: 2026-09-29 · 브랜치: `fix/benefit-class-hint` · 워크트리: `.worktrees/benefit-class-hint`

## 배경
하네스 표본 `이남순.tif`(22칸)·`김애란1.tif`(17칸)에서 인쇄가 공란인 `급여구분`이 `급여`로 채워졌다. 두 문서는 하네스 ①' 재추출(AO 값 없음)로 Docraft가 세부내역서를 뽑았고, `verify.py` `BLANK_AO`(626행)가 Docraft 값을 그대로 채택했다.

## 원인 경로
* `급여구분`을 채우는 후처리 규칙은 없다. `rules._class_checks`(1449행)는 값이 비면 건너뛰고, 다른 곳(`rules.py` 691·693·1422행)은 이미 있는 값을 읽기만 한다.
* 값의 출처는 VLM 추출이며, 스키마 설명(`backend/doctypes.py` 120행)이 "급여 또는 비급여"뿐이라 공란 칸도 모델이 고르게 되어 있었다(다른 표 칸은 `TABLE_HINT`가 붙고 `급여` 칸은 "총액에서 계산하지 않는다"가 있다).

## 수정
`급여구분` 설명을 "급여구분 열(구분·급/비·비급 등)에 인쇄된 값만. 칸이 비었거나 열이 없으면 null. 금액 열·항목으로 추정하지 않는다. '비급'은 비급여로 본다." + `TABLE_HINT`로 바꿨다. `tests/test_rules.py`에 설명 검증 테스트를 더했다. 하네스 공유 파일은 건드리지 않았다.

## 실측
* 개발 서버 Docraft에 배포하지 않고, 로컬 코드 + 서버 PaddleOCR(SSH 터널) + OpenRouter `qwen/qwen3-vl-32b-instruct`로 실행했다.
* 수정 전(dev 코드, `verify.read` 1회): 이남순 22칸 전부 null(정답 공란과 일치), 김애란1 18칸 중 17 일치('비급' 칸을 null로 놓침), 3022030712433802-1 20칸 중 18 일치('80/100' 칸 불일치), 3022033116480603-1 12칸 전부 일치. 즉 이번 로컬 실행에서는 `급여` 오채움이 재현되지 않았다(기록의 오채움은 모델 변동 또는 이전 서버 버전 실행값으로 추정).
* 테스트: 전체 621건 통과.

## 수정 후 실측 (서버 재기동 뒤, 같은 방식)
컨테이너 IP가 바뀌어 터널 대상을 갱신했다. `verify.read` 문서당 1회, 이남순은 `verify.run`(AO 비움) 1회도 실행했다.

| 문서 | 수정 전 일치 | 수정 후 일치 |
|---|---|---|
| 이남순.tif | 22/22 | 22/22 (`verify.run`도 22칸 null) |
| 김애란1.tif | 17/18 | 17/18 ('비급' 행 null 유지) |
| 3022030712433802-1.png | 18/20 | 18/20 (인쇄된 급여 그대로, '80/100' 행 불일치) |
| 3022033116480603-1.png | 12/12 | 12/12 |

수정 후가 수정 전보다 나빠진 칸은 없다(칸별 값이 전/후 동일). 다만 수정 전에도 오채움이 재현되지 않아 개선 효과는 이 실행으로 입증되지 않았다. 판정: 병합 가능.
