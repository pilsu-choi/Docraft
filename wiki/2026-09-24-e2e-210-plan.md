# 7종 210장 e2e 테스트 계획

- 날짜: 2026-09-24
- 브랜치: `docs/e2e-210-plan`
- 워크트리: `.worktrees/e2e-210-plan`

지금까지 e2e는 세부내역서·진료비영수증 57건만 돌렸다([e2e AO 대비 비교](2026-09-24-e2e-ao-verify.md), [e2e 엣지케이스](2026-09-24-e2e-edge-cases.md)). 다음 테스트는 7종(진단서·소견서·수술확인서·입퇴원확인서·진료비영수증·세부내역서·약제비영수증)을 30장씩, 모두 210장 돌린다. 정확도만 보지 않고 **단계별 소요 시간과 결과를 모두 모아 통계 데이터로 쓴다**.

## 수집 항목

문서 한 장마다 한 행을 남긴다. 나중에 유형별·단계별로 집계할 수 있도록 원시 값을 남긴다.

| 구분 | 항목 | 출처 |
|---|---|---|
| 식별 | 문서 유형, 파일명, 쪽수, AO `transaction_id` | 샘플 폴더, AO 응답 |
| 소요 시간 | AO 2.0 접수→결과 수신(초), 폴링 횟수 | `e2e/run_pipeline.py` `run_log.csv` `소요초` |
| | harness-v2 처리(초) | 같은 로그(AO와 나눠서 기록해야 함, 아래 참고) |
| | Docraft `/api/verify` 처리(초) | `scripts/verify_e2e.py` `*.run.log` |
| | 전체(초) = AO + harness + Docraft | 계산 |
| 상태 | AO 성공·실패·타임아웃, harness 성공·실패, Docraft 성공·실패와 오류 메시지 | 각 로그 |
| 결과 원본 | AO 응답 JSON, harness 결과 JSON, Docraft 결과 JSON | `out/ocr`, `out/harness`, `data/verify/<실행>/` |
| 정확도 | AO 단독, AO+harness, AO+Docraft 칸별 판정(일치·불일치·누락·오검출·제외) | `make_report.compare` |
| Docraft 동작 | 값을 바꾼 칸 수, Judge 호출 수, `review` 표시 수, 걸린 룰 id | Docraft 응답 `counts`·`verify.trace` |

집계할 통계:

- 유형별 단계 소요 시간: 평균·중앙값·p90·최대, 전체 벽시계 시간(동시 처리 수 함께)
- 유형별 정확도: AO 단독 → 최종, 필드·열별 오류 순위
- 실패율(AO 타임아웃, harness 실패, Docraft 실패)
- 개인정보 필드(성명·주민번호·등록번호·주소·연락처)를 뺀 정확도를 따로 낸다. 현재 채점기는 개인정보 필드도 채점한다(`scripts/verify_eval.py` `score()`, `e2e/make_report.py` `judge()`).

## 소요 시간 추산

### 실측 근거 (세부내역서·진료비영수증 57~60건)

| 구간 | 기록 | 결과 | 건당 소요 | 동시 처리 |
|---|---|---|---|---|
| AO 2.0 → harness-v2 | `e2e/out/run_log.csv` (2026-09-22) | 60건 중 52건 성공 | 성공한 건 평균 115초, 최대 314초 | 3 |
| Docraft `/api/verify` | `data/verify/e2e-20260924.run.log` | 57건 모두 성공 | 평균 103초, 중앙 96초, 최대 280초 | 4 |
| | `e2e-20260924b.run.log` | 57건 | 평균 120초, 중앙 106초, 최대 240초 | 4 |
| | `e2e-20260924c.run.log` | 52건 | 평균 154초, 중앙 148초, 최대 331초 | 4 |

- AO 실패 8건은 모두 폴링 한도(`POLL_MAX` 60회 × 5초 ≈ 300초)를 넘겨 `status=running`인 채 끝났다. 모두 진료비영수증 `공란다수_*` 파일이었다.
- `run_log.csv`의 `소요초`는 AO와 harness를 합친 시간이다. 이번에는 둘을 나눠 기록해야 한다.

### 210장 추산

| 단계 | 계산 | 추산 |
|---|---|---|
| AO 2.0 + harness-v2 | 210 × 115초 ÷ 3 | 약 2.2시간 |
| AO 실패분 재처리(약 13%) | 약 27건 | +20~30분 |
| Docraft `/api/verify` | 210 × 약 130초 ÷ 4 | 약 1.9시간 |
| **합계(단계를 차례로)** | | **약 4~4.5시간** |
| 여유 포함 | | **5~6시간** |

- AO 단계가 끝난 유형부터 Docraft를 돌리면(파이프라인으로 겹쳐 돌리기) 3시간대까지 줄일 수 있다.
- 5종(진단서·소견서·수술확인서·입퇴원확인서·약제비영수증)은 e2e 소요 시간을 잰 적이 없다. 여러 쪽짜리 문서가 섞이면 건당 시간이 늘어난다.
- demo-ao(`https://demo-ao.agilesoda.ai`)는 공용 서버라 부하에 따라 시간이 크게 흔들린다. workers를 늘려도 AO가 병목이 되면 빨라지지 않는다.

## 실행 전 점검

1. `POLL_MAX`를 60에서 120 정도로 올린다. 그대로 두면 약 10%가 타임아웃으로 떨어진다.
2. 새 5종에서 유형마다 3장씩 먼저 돌려 건당 시간을 재고 추산을 고친다.
3. `run_pipeline.py`가 AO와 harness 시간을 나눠 기록하도록 고친다.
4. 5종의 정답지(`정답지/<유형>/*_merged.json`)가 있는지 확인한다. 지금은 세부내역서·진료비영수증만 있다.
5. Docraft AWS 서버 배포 커밋을 기록해 둔다(`DEPLOYED`). 같은 코드로도 재실행하면 결과가 흔들린다(직전 실행 대비 나빠짐 23·좋아짐 24, [e2e 엣지케이스](2026-09-24-e2e-edge-cases.md)).
