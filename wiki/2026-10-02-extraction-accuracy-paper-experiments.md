## 1. 목적

최종 Key-Value 정확도를 99% 가까이 올린다. 기준 지표는 전체 정확도가 아니라 아래 네 가지다.

| 지표 | 뜻 |
|---|---|
| ① 자동 적재 칸 오류율 | 사람 검토 없이 나가는 칸(`pass`, 판정 없는 칸) 중 틀린 비율. 고객사가 받는 품질 |
| ② 자동 적재 비율 | 오류율 1% 이하로 고정했을 때 자동 처리되는 칸의 비율 |
| ③ 하네스가 망친 칸 | AO가 맞았는데 하네스가 틀리게 바꾼 칸. 0이어야 한다 |
| ④ 문서당 시간·VLM 호출 수 | 재판독 비용 |

## 2. 후보 기법과 근거 논문

논문을 통째로 비교하지 않고 기법 단위로 하나씩 켜고 끈다. 존재는 arXiv 초록 페이지에서 확인했다(본문 수치는 미확인).

| | 기법 | 근거 논문 | 주 지표 | 데이터 |
|---|---|---|---|---|
| A | 재판독으로 바뀌는 값의 근거 위치 검증(근거 박스 겹침·라벨 거리·잘라 다시 읽기) | Towards Reliable and Interpretable Document QA via VLMs (2509.10129), ExtractBench (2607.29677) | ③ | r6에 근거 박스 96칸뿐 → Docraft 응답 원문 보존 후 AWS 1회 |
| B | AO·Docraft 불일치 + 규칙 결과 + AO 신뢰도를 합친 자동 적재 게이트, 문서 단위 보정 | ExtractConf (2606.24420), Valid Per-Field Selective Risk Control (2608.14639), When Can Conformal Risk Control Certify LLM Outputs? (2606.29054), ConfBench (2608.01792) | ①② | r6로 바로 가능(불일치 신호는 검토 칸에만 있음) |
| C | 오류 유형별로 처리 방식 정하기(규칙·마스터 / 잘라 재판독 / 행·열 재탐색 / 검토) | OCR or Not? (2603.02789), DocClaw (2608.18685) — 자유 반복 에이전트는 "판단은 하네스 한 곳" 원칙과 충돌해 고정 표만 채택 | ①③ | r6로 바로 가능 |
| D | 셀·행 단위로 잘라 확대해 재판독 | MinerU2.5 (2509.22186), ReceiptBench (2605.22413), AwaRes (2603.16932) | ①④ | VLM 새 호출 → A·B 이후 |
| E | 재판독 프롬프트에 레이아웃 보존 AO 텍스트 동봉 | VAREX (2603.15118), ConfBench | ① | VLM 새 호출 → A·B 이후 |

제외: 강화학습(GRPO, olmOCR 2·Table-R1)은 정답지가 205건 이상 쌓인 뒤 검토. 여러 번 읽어 다수결(Self-Consistency)은 ExtractConf에서 구분력이 약하다고 보고돼 뺐다.

## 3. 진행 순서

1. **오프라인 분석(B·C)**: `e2e/exp_gate_routing.py`로 r6(`e2e/out/golden1002-aws-r6/`, harness 9695984) 채점 칸과 하네스 칸별 근거를 묶어 분석한다. 결과 `e2e/out/exp-1002-gate/report.md`. AWS 호출 없음.
2. **근거 데이터 보존(A 준비)**: `DOCRAFT_KEEP_RESPONSE=true`일 때 `harness.fallback.documents[].response`에 Docraft `groundings`·`field_quality` 원문을 함께 싣는다(지금은 `fields` 값만). 기본 출력은 바뀌지 않는다.
3. **AWS 1회 실행**: 2를 dev에 push한 뒤 배포 담당 세션(6c)에 요청한다. 다른 세션 배포와 합쳐 59건을 한 번만 돌린다.
4. **A 오프라인 실험**: 3의 결과로 근거 검증 규칙을 켜고 끈 효과를 계산한다. 마음에 들면 하네스 규칙으로 구현한다.
5. **D·E**: A·B 이후 남은 오류를 보고 결정한다.

과적합 방지: 59건으로 기법과 문턱값을 고르고, 검수 중인 205건으로 최종 확인한다. 유의성은 문서 단위로 다시 뽑아(bootstrap) 판단한다(같은 문서 안의 칸은 오류가 몰린다).

## 4. 데이터 현황 (r6 기준)

- 칸 노드: `confidence`(AO), `predicted_value`(AO 원값), `value`, 판정 칸에만 `harness{tier, decision_rule_no, evidence{rule[], reread{quality, grounding}}, ao_value}`. 필드 1133개 중 573개, 표 칸 13473개 중 4144개에 판정이 있다.
- AO API 응답(04)에는 좌표가 없다. 근거 박스는 Docraft가 읽은 칸에만 있다(필드 42·표 54칸). `label_bbox`는 이번 산출물에 없다.
- `reread_mode=off`라 Docraft 불일치 신호는 ④' 검토 칸에만 있다(표본 편향).
- `e2e/replay_harness.py`는 Docraft·parse를 건너뛴다. 녹화 응답 재생은 `DocraftClient(client=httpx.Client(transport=MockTransport))`로 가능하지만 응답 원문이 필요하다(2단계).

## 6. 기대 칸 검사(표 완결성) 설계 — 2026-10-02

### 6.1 사전 조사 (`e2e/exp_expected_cells.py`, 결과 `e2e/out/exp-1002-expected/`)

- 행 종류 판별은 이미 있다: 합계·소계·끝수 조정은 `rules/builtins.py` `excluded_row_reason`, 섹션 제목은 `normalizer/value_fix.py` `is_section_row`. 나머지가 항목 행이다.
- 인쇄 열은 AO parse 표 머리글에서만 알 수 있다: `normalizer/parser_fill.py` `detail_printed`(세부내역서), `uncovered_form`(영수증). 출력 `harness.parser`에는 머리글이 남지 않는다.
- 기존 누락 검사(룰 1·2)는 `normalizer/coverage.py` `coverage_review` → 문서 `unresolved`·`review_paths` → ④' Docraft 폴백 → 근거 있으면 채택. 설정은 `rulesets/shared/receipt_items.yaml`(Docraft와 같은 바이트여야 함).
- 하네스 누락 52칸의 등급: pass 20·repaired 20·untouched 7·unresolved 5 — **90% 이상이 검토 표시 없이 나갔다.**
- 정답지 채움률 단순 규칙(채움률 ≥95%·n ≥20인 열×행 종류를 필수로): 표 누락 48칸 중 18칸 검출(재현율 37.5%), 정밀도 32~42%. 검출은 거의 `항목`(병합칸 분류명). 놓친 것은 투여량 20칸 — 한 서식에서 **열이 통째로 빈** 경우라 칸 단위 채움률로는 못 잡는다. 오경보는 인쇄 열을 정답으로 근사한 탓이 크다(2개 문서에 몰림).

### 6.2 설계

두 검사를 `coverage_review`의 룰 3으로 넣는다. 새 등급·새 경로를 만들지 않고 기존 룰 1·2와 같은 흐름(문서 `unresolved` → ④' Docraft → 근거 있으면 채택, 아니면 검토)을 탄다. 값은 만들지 않는다.

| 검사 | 조건 | 잡는 유형 |
|---|---|---|
| 3a 열 통째 누락 | parse 머리글에 인쇄된 열인데, 항목 행 전체에서 그 열이 모두 비었다 | 투여량 열 누락 같은 서식 단위 누락 |
| 3b 필수 칸 누락 | 행 종류별 필수 열(설정) 중 인쇄된 열의 칸이 비었다 | 병합칸 분류명·개별 칸 누락 |

- 인쇄 열을 모르면(parse 실패·머리글 없음) 3a·3b 모두 건너뛴다. 추측으로 기대하지 않는다.
- 설정은 `receipt_items.yaml`에 `required_cells: {문서종류: {행종류: [열...]}}`로 두고 Docraft 사본도 같이 바꾼다. 처음 값은 정답지 채움률 100%인 열만 보수적으로 넣는다(6.1 권고). 205건 검수본으로 다시 검증한다.
- 진단용으로 인쇄 열 집합을 `harness.parser.documents[].printed`에 남겨 오프라인 분석이 가능하게 한다.
- 효과 측정: 채점 정확도는 Docraft가 채워야만 오르므로 ① 자동 적재 칸 오류율(누락이 검토로 빠지는가)과 ② 검토로 빠지는 정상 칸 수를 함께 본다. AWS 다음 배포에서 59건으로 확인한다.
